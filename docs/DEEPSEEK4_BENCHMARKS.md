# DeepSeek V4: замеры GPU-only на этом ПК

Это исходные замеры до оптимизации передачи. Текущий профиль Q3 использует LRU
отдельных матриц; последующие результаты: [DEEPSEEK4_EXPERT_STREAMING.md](DEEPSEEK4_EXPERT_STREAMING.md).

Дата: 3 октября 2026 года. Windows, Ryzen 9 9950X (16 ядер / 32 потока),
128 ГиБ RAM (125,55 ГиБ доступно Windows), RTX 5090 32 ГиБ, Samsung 990 Pro.
CUDA 13.0, backend `strata-deepseek4`, llama.cpp
`3cf03257f219afbe7334045ff7c6a06ac68c627d`. Сборка для CUDA architecture 120.

В каждом вычислении scheduler проверяет назначение операций. Для этих запусков
подтверждены `cpu_compute_nodes=0`, `expert_matmuls_gpu=129`. Хранение экспертов
в RAM/mmap не означает выполнение математики на CPU. CPU обслуживает копирование,
токенизацию, sampling и протокол. MTP в этих замерах выключен.

## Веса и настройки

Размеры прочитаны из заголовков и геометрии тензоров GGUF. Обе модели имеют 43 слоя,
256 экспертов на слой, 6 выбранных экспертов и 1328 тензоров. Все части проверены
на наличие данных до конца последнего тензора; контрольные суммы не вычислялись.

| Настройка | UD-Q8_K_XL | UD-Q3_K_XL |
|---|---:|---:|
| Части GGUF | 5 | 4 |
| Все веса, байт | 161 864 270 172 | 128 201 384 284 |
| Все веса, ГиБ | 150,75 | 119,40 |
| Routed experts, ГиБ | 137,0625 | 112,125 |
| Формат экспертов | MXFP4 | IQ3_XXS + MXFP4 |
| Постоянно в VRAM, слоёв экспертов | 0 | 6 последних |
| Их размер, ГиБ | 0 | 15,5625 |
| Batch prefill | 512 | 4096 |
| Контекст | 8192 | 8192 |
| Host threads | 1 | 1 |

Это сравнение двух рабочих конфигураций. Отличаются и квантование, и размещение
экспертов: числа не выделяют эффект одного только квантования.

## Результаты

| Запуск | Запрос, токенов | Prefill, с | Ответ, токенов | Decode, с | Decode, токенов/с |
|---|---:|---:|---:|---:|---:|
| Q8: проверка контекста | 513 | 54,192 | 2 | — | — |
| Q8: генерация | 36 | 12,796 | 128 | 68,386 | **1,87** |
| Q3: проверка контекста | 4096 | **61,753** | 3 | — | — |
| Q3: первая генерация | 36 | 8,462 | 128 | 37,866 | **3,38** |
| Q3: повтор генерации | 36 | 0,247 | 128 | 26,510 | **4,83** |

4096 токенов Q3 обработаны со средней скоростью около 66,3 токена/с.
Проверка контекста использовала записи вида «Запись N: синий квадрат» и вопрос
о цвете; ответ Q3 — «синие». Для точных 4096 токенов сохранялись первые 4080 и
последние 16 токенов отформатированного запроса. Это синтетический тест пропускной
способности, а не оценка качества на длинных документах.

Запрос генерации: «Напиши подробное объяснение на русском: как устроен кэш
процессора и чем L1 отличается от L2 и L3». Greedy decoding, thinking выключен,
лимит 128 токенов. Повтор Q3 вернул те же 128 token IDs; восстановлены 35 из 36
токенов prompt. Prefill повторного запроса включает восстановление snapshot и
пересчёт последнего токена. Токены самого ответа всё равно вычисляются заново.

OS file cache не очищался. «Первая» означает первую генерацию данного запроса
в процессе после проверки контекста; это не гарантированно холодный SSD.
Повтор выигрывает одновременно от состояния сессии и прогретых страниц весов.
Короткие ответы в 2–3 токена не используются для оценки устойчивой скорости decode.

## Нагрузка и память Q3

Сэмплы приблизительно раз в две секунды. CPU процесса нормирован на 32 логических
потока, как общий процент в Task Manager. GPU util и VRAM относятся ко всей карте,
включая другие приложения. Финальное освобождение модели исключено из сводки.

| Фаза | CPU процесса, среднее | CPU процесса, максимум | GPU util, среднее |
|---|---:|---:|---:|
| Prefill 4096 | 1,64% | 2,14% | 6,9% |
| Первая генерация 128 | 2,53% | 2,87% | 24,2% |
| Повтор 128 | 3,11% | 3,13% | 40,4% |

Максимальная занятая VRAM — 29 269 МиБ (28,58 ГиБ). Working set процесса достиг
106,13 ГиБ; минимум доступной системной RAM — 3,68 ГиБ. Это измеренные пики выборки,
а не гарантированные пределы. Новый архив сессии при свободной RAM ниже 8 ГиБ
не создаётся. Точное восстановление уже существующего snapshot не требует его
удаления и повторного выделения памяти.

GPU-only режим работает, но карта не занята вычислениями постоянно. С учётом
подгрузки выбранных экспертов и низкого GPU util задержки передачи/чтения весов
остаются кандидатом для следующего профилирования. Эти замеры не разделяют время
SSD, page faults, pageable-memory staging, PCIe и CUDA kernels. Для контекстов
больше 4096 токенов времени обработки пока не измеряли.

## Повторить

Профили запускаются по очереди; перед тестом нужно завершить другой модельный
процесс. Готовый Q3-профиль: `strata-deepseek4-ud-q3-k-xl.json`.

```powershell
.venv\Scripts\python.exe tools/benchmark_deepseek4.py --config strata-deepseek4-ud-q3-k-xl.json --prompt-tokens 4096 --tokens 128
```

Инструмент сохраняет JSON с параметрами, временами, output IDs и сэмплами нагрузки,
а также журнал GPU-аудита в `bench/results`. Каждый запрос ограничен временем;
по завершении модель освобождается. Параметр `--timeout` задаёт предел в секундах.
Файловый кэш ОС инструмент не очищает.

Запуск web/API после теста: `run-deepseek4-ud-q3-k-xl.bat`.
Qwen запускается прежним `run-q8_0.bat`, тяжёлая версия DeepSeek — `run-deepseek4.bat`.
