# Чтение экспертных матриц непосредственно из GPU-кэша

11 октября 2026 реализован отключаемый путь для короткого MMVQ-decode:
IQ3_XXS, MXFP4 и Q8_0 читаются по адресам матриц в GPU-кэше. При попадании
промежуточная D2D-копия в рабочий тензор больше не нужна. Первое сравнение
B/A/A/B с прежней сборкой: **18,266 → 18,601 ток/с, +1,84%** для поздних
прогретых повторов. Среднее всех четырёх повторов: **+1,16%**.

ПК: RTX 5090 32 ГиБ, Ryzen 9 9950X, 128 ГиБ RAM, Windows, CUDA 13.0.
Target — DeepSeek V4 Flash 0731 UD-Q3_K_XL на H: (Samsung 990 PRO 4 ТБ),
DSpark Q8_0 с draft-max 2. Target-кэш 15360 МиБ, draft-кэш 1024 МиБ,
staging 16 МиБ, slabs 16 МиБ, frequency admission и асинхронный конвейер.
Предыдущая оптимизация пакетного D2D включена в обоих вариантах.

## Как устроено

- Scheduler перед передачей выбранной матрицы подготавливает таблицу из
  256 GPU-адресов. Начальное значение каждого адреса указывает в обычный
  рабочий тензор. Попадания в кэш заменяют соответствующие адреса.
- Таблица занимает 2048 байт. Один небольшой kernel получает её содержимое
  по значению, поэтому нет асинхронного чтения переиспользуемого host-массива.
- MMVQ выбирает адрес по исходному expert ID. Сохраняются квантованные данные,
  индексы bias, gate/up fusion, порядок dot product и редукций. Отдельные
  адреса поддерживаются для основной и gate-матрицы fused-операции.
- Адрес самой таблицы стабилен при CUDA Graph capture/replay; содержимое
  обновляется перед каждым выполнением, даже когда попаданий нет.
- Выбранные cache allocations защищены от вытеснения до постановки чтений
  потребителя в CUDA streams. При использовании нескольких streams их
  события упорядочиваются относительно потока владельца кэша.
- Если подготовленное вычисление отменено до запуска, удержанные матрицы
  материализуются обычным D2D до освобождения записей. Это проверено отдельно.

Новые cache admissions и промахи пока используют прежний путь. Длинный
prefill, MMQ и неподдерживаемые формы тоже сохраняют материализацию.
Ограничения первого варианта: NVIDIA, не более 256 экспертов, contiguous
веса без view, K кратен 256, M кратно 128, не более восьми токенов и не выше
лимита MMVQ конкретного типа/GPU. Проверка полных плиток нужна, поскольку
MMVQ может читать строки до маскирования выхода; cache entry содержит лишь
512 байт дополнительного хвоста. При `STRATA_DS4_ROUTED_MMQ=1/2` прямой путь
консервативно отключается. Upstream `third_party` и Qwen-движок не менялись.

## Измерения

Одна серия: prefill 4096, decode 32, четыре повтора decode из RAM-сессии,
затем полный prefill в новой сессии. OS cache не очищался. Порядок процессов:
B1, A1, A2, B2. A — сохранённая прежняя обычная сборка, B — новая сборка
с прямым чтением. Численные эксперименты ATTENTION/PROJECTION и COST выключены.
Это сравнение с прежним бинарником, а не только переключение флага в новом.

| Метрика | A | B |
|---|---:|---:|
| Среднее repeat_3/4, ток/с | 18,266 | 18,601 |
| Среднее всех четырёх повторов, ток/с | 17,571 | 17,774 |
| Повторный полный prefill 4096, мс | 9019,09 | 8955,76 |

Дополнительная B/A-пара финальной сборки с ответами по 128 токенов и двумя
прогретыми повторами: **13,923 → 14,144 ток/с (+1,59%)**. Выходные IDs
совпали. Это более длинная генерация на том же запросе, а не замер скорости
на произвольных диалогах или длинном входном контексте.

Небольшое изменение prefill не считаем подтверждённым ускорением: новый
путь там не используется. Все выходные token IDs и draft acceptance
совпали между четырьмя процессами. В каждом B за весь процесс пропущены
87550 D2D-копий target-матриц (319328281600 байт) и 3837 копий DSpark
(17101355520 байт). Счётчики включают прежние хвосты копирования, а не
только полезные байты матриц. Вынужденной материализации при этих запусках нет.

Во всех 20 запросах decode физические чтения H: равны нулю. Это счётчик
всего устройства; вывод относится именно к этим запросам. Максимальная
наблюдавшаяся загрузка процесса — 5,83% CPU, нормированная на 32 логических
процессора; VRAM всего устройства — до 31165 МиБ. Аудит везде показывает
`cpu_compute_nodes=0`. CPU продолжает управлять передачами и читать RAM.

Ускорение невелико: удалена промежуточная передача внутри VRAM. Загрузки
H2D, промахи кэша и вычисления модели остаются. Проценты этого сравнения
нельзя складывать с результатами предыдущих этапов.

## Проверки

- Все 184 пары контрольных сумм полных logits и argmax совпали на фиксированной
  истории: prefill 4096, decode по одному и по три токена. H2D и cache hit/miss
  счётчики target совпали; D2D уменьшился ровно на 556934331392 байта.
- GPU fixture оставляет scratch-матрицы заполненными `0xA5`, проверяет отсутствие
  D2D при попадании и сравнивает полный результат побитово с обычным MMVQ.
  Охвачены три типа весов, N=1/2/3/4/8/9, одна и шесть входных lanes,
  IDs с шагом 256, обе стороны gate/up fusion, смешанные попадания и промахи.
- Повторное использование CUDA Graph проверяется после уменьшения кэша,
  полного опустошения, повторного роста и изменения адресов allocations.
  Проверены fixed arena, dynamic cache, slabs, pipeline on/off и graphs on/off.
- Финальная сборка прошла 19 CTest, включая пять новых конфигураций direct-cache,
  существующие transfer, GPU-only, speculative, attention и routed MMQ проверки.
  Пять direct-конфигураций выполнили по 2052 побитовых сравнения; дополнительный
  запуск с MMVQ token-batch=2, graphs, pipeline и slabs дал ещё 2052 точных
  результата. Неполные плитки и weight views отклоняются подготовкой.
- Реальные сессии DSpark: восемь greedy-сценариев совпали с предыдущей
  DSpark-сборкой; проверки сохранения/восстановления, продолжения, отмены
  prefill/decode и повторяемости seeded sampling прошли. Здесь reference —
  предыдущая сборка с DSpark, а не serial target без draft.

Это проверка сохранения прежней арифметики, не новое доказательство
batch/serial-паритета обычного численного режима модели.

## Включение и артефакты

Нужны оба флага: сборка `-DSTRATA_DEEPSEEK_DIRECT_CACHE_EXPERIMENT=ON`
и `"STRATA_DS4_DIRECT_CACHE": "1"` в `env` профиля. Оба общих default — OFF.
В локальном `strata-deepseek4-ud-q3-k-xl-dspark.json` режим включён; основной
бинарник пересобран с DIRECT_CACHE=ON. ATTENTION, PROJECTION и COST остаются OFF.
Следующий запуск обычного launcher использует прямое чтение.
Параметр применяется при следующем запуске процесса. Если бинарник собран
без поддержки, явное включение завершается ошибкой вместо молчаливого игнорирования.
Для отката достаточно убрать runtime-флаг. Пакетный D2D может оставаться включённым.

Код: `expert_direct_cache.cuh`, `expert_direct.cuh`, `DirectMmvqPatches.cmake`,
`cuda_expert_transfer.inc`, `expert_pipeline_scope.inc`, `test_expert_direct.cpp`
в `backends/deepseek4`. Изменения CUDA/MMVQ применяются к приватным generated sources.

Артефакты в `bench/results/`:

- `ds4-cache-read-20261011-{a1,a2,b1,b2}.json` и `.log` — B/A/A/B;
- `ds4-cache-read-20261011-summary.json` — сводка, CPU/VRAM, SSD и счётчики;
- `ds4-cache-read-20261011-fixed-{a,b}.json` — 184 контрольные пары и SHA256 бинарников.
- `ds4-cache-read-20261011-long-{a,b}.json` — дополнительная пара 128 токенов;
- `ds4-cache-read-20261011-validation-{a,b}.json` — реальные сессии и сравнение 8/8.
- `ds4-cache-read-20261011-fixed-final.json` — повторные 184 точные пары финального бинарника.

SHA256 предыдущего бинарника:
`fa9de0c579011bc5edce519d356c3c10a0d9483ac55e09c3a83d4c406bf38bdd`.
