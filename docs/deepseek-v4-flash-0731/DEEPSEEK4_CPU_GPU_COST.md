# Стоимость GPU-ветки и конкуренция CPU/H2D

13 октября 2026. Продолжение этапа 4 после
[первой калибровки](DEEPSEEK4_CPU_CALIBRATION.md). Профиль v2 учитывает
GPU-арифметику, замедление CPU и передачи при совместной работе, измеренное
перекрытие GPU/H2D. На короткой серии A/B/B/A ускорение не подтверждено:
16,60 → 16,53 с, decode около 3,41 ток/с у обоих вариантов.
CPU получил на 12,5% меньше экспертных строк. Этап 4 остаётся открытым.

Следующая серия — [прерывистые запуски и настройка пула](DEEPSEEK4_CPU_POOL_TUNING.md):
профиль v3 учитывает паузы между CPU-заданиями, отдельно проверены spin/sleep
и размер заданий. Приведённые ниже результаты относятся к сборке v2.

## Что реализовано

- [Калибратор](../../backends/deepseek4/cpu_calibrate.cu) повторяет все 33
  распределения CPU-работы на формат под фоновой передачей pinned RAM → GPU.
  Постоянный поток копирования вращает восемь банков, не изменяя их содержимое.
  Сохраняются времена CPU-фаз и передачи, включая исходные пробы.
- [GPU-проба](../../backends/deepseek4/cpu_calibrate_gpu.cuh) вызывает те же
  совместимые Q8_1, MMVQ, SwiGLU и маски пропуска CPU-строк, что используются
  движком. Замер включает квантование, gate/up, SwiGLU, квантование hidden и down.
  CPU join и итоговое взвешенное суммирование сюда не входят.
- Измерены окна 1–4 токена, 0–4 CPU-строки, повторяющиеся и разные эксперты,
  сгруппированные и распределённые маски. Используется настоящий top-k=6 из
  fixture, всего 80 GPU-случаев на формат. Профиль не принимается при другом
  top-k. Для каждой формы план берёт максимум медиан четырёх размещений.
- GPU-время измеряется CUDA events при повторном запуске CUDA Graph. Перед
  каждой пробой вне измеряемого интервала заполняется буфер 256 MiB, чтобы
  уменьшить влияние многократного чтения весов из L2. Это не аппаратное
  доказательство полного вытеснения кэша.
- Последовательный и параллельный запуск GPU-вычислений/H2D сравниваются в
  пяти чередующихся A/B/B/A раундах; первый — прогрев. Оба stream используют
  общее начальное событие. Сохраняются восемь проб каждого режима.
- [Профиль](../../backends/deepseek4/cpu_cost_profile.cpp) проверяет полноту,
  уникальность и допустимость GPU-измерений. Привязка к сборке, оборудованию,
  потокам, форматам и геометрии сохранена. Профиль неизменен внутри процесса.
- В CPU TSV добавлены `predicted_gpu_compute_us` и `predicted_gpu_branch_us`:
  можно отличить стоимость ядер от оценки всей ветки с передачей.

Формула выбора:

```text
H2D = уникальные оставшиеся байты × стоимость байта
GPU = H2D + GPU_ядра - min(H2D, GPU_ядра) × доля_перекрытия
T = max(CPU_полная_группа, GPU) + стоимость_очереди
```

При одновременной CPU-работе и оставшейся передаче используются максимумы
изолированной и нагруженной стоимости CPU/H2D. При отсутствии конкурирующей
ветки — изолированные значения. Это консервативная оценка: она распространяет
измеренное замедление на всю передачу, даже если CPU закончит раньше.
Сохраняются нулевой вариант CPU, запас 3%, бюджет 2000 мкс на токен и выбор
только по текущим ID и уже зафиксированному префиксу.

Доля перекрытия равна `(serial - parallel) / GPU_ядра`, ограничена диапазоном
0–1. Отрицательный результат не даёт скидки. Передачи идут в независимый
staging: проба оценивает возможность перекрытия, но не воспроизводит зависимости
загрузки конкретных весов в полном MoE. Пока используется одна точка — три
токена, три CPU-строки, передача восьми экспертных троек. Перенос её доли на
другие формы — приближение, а не измерение каждого случая.

## Измерения на этом ПК

Ryzen 9 9950X, RAM 128 GiB, RTX 5090 32 GiB, Windows, MSVC 2022, CUDA 13.0.
Профили заново измерены на 8/12/16 потоках. Геометрия 4096×2048, clamp 10;
восемь pinned банков больше суммарного L3 CPU. В CPU-интервале нет чтения SSD.
IQ3_XXS/IQ3_XXS/MXFP4 и MXFP4 берутся из сохранённых GGUF-экспертов target.
Q8_0 получен преобразованием этих весов для пробы формата; это ещё не реальные
записанные Q8-эксперты DSpark.

Результаты на 12 потоках, мкс. CPU считает три активации одного эксперта;
H2D — одну тройку gate/up/down; GPU — три токена с шестью экспертами на токен.

| Форматы gate/up → down | CPU отдельно / с H2D | H2D отдельно / с CPU | GPU все строки / без трёх CPU-строк |
|---|---:|---:|---:|
| IQ3_XXS → MXFP4 | 1723 / 1674 | 756 / 799 | 161 / 154 |
| MXFP4 → MXFP4 | 1204 / 1253 | 928 / 974 | 183 / 173 |
| Q8_0 → Q8_0 | 1371 / 1376 | 1854 / 1904 | 335 / 298 |

В IQ3 план использует 1723 мкс: случайное ускорение нагруженной пробы не
уменьшает прогноз. Передача под CPU-нагрузкой замедлилась на 2,7–5,6%.

| Форматы | Последовательно, мкс | Параллельно, мкс | Принятая доля перекрытия |
|---|---:|---:|---:|
| IQ3_XXS → MXFP4 | 6341 | 6375 | 0 |
| MXFP4 → MXFP4 | 7741 | 7846 | 0 |
| Q8_0 → Q8_0 | 15469 | 15387 | 0,274 |

Для IQ3/MXFP4 параллельная проба не сократила время. Единственная положительная
оценка получена для Q8 на 12 потоках; на 8 и 16 потоках она равна нулю.
Поэтому полное перекрытие не предполагается автоматически. Маленький выигрыш
Q8 в одной серии ещё не доказывает устойчивой пользы такого перекрытия.

## Проверка полного запроса

UD-Q3_K_XL + DSpark Q8_0, контекст 8192, draft-max 2, GPU-кэш target 15 GiB,
draft 1 GiB, общий RAM-кэш 2 GiB, демоция 16 MiB, 12 CPU-потоков, cap=1.
Включены совместимые AVX2/SwiGLU, GPU-очереди CPU/fetch, перекрытие подготовки
контекста; CUDA Graphs разрешены, host TSV включён у обоих вариантов.

Один бинарник, один профиль, порядок base → full → full → base. Base выключает
учёт конкуренции и GPU-стоимости двумя флагами; full включает оба. Каждый
свежий процесс сначала прогревается запросом на 16 выходных токенов, затем
выполняет новые запросы с 372 и 15 входными токенами, по 16 выходных. Session ID
различаются; восстановления KV-префикса нет. Время — сумма двух измеряемых
запросов без запуска процесса и прогревочного запроса.

| План | Два повтора, с | Медиана, с | Decode, ток/с | CPU-seconds, медиана |
|---|---|---:|---:|---:|
| Без новых компонентов стоимости | 16,563 / 16,641 | 16,602 | 3,410 | 58,43 |
| С GPU и конкуренцией за память | 16,468 / 16,594 | 16,531 | 3,406 | 57,29 |

Разница полного времени −0,43%, decode практически одинаковый: ускорение не
засчитывается. Все выходные token IDs совпали. Суммарно с прогревом новый план
назначил CPU 587 строк вместо 671 (−12,5%), число заданий — 330 вместо 361.
CPU-seconds уменьшились на 1,95% в этой небольшой серии.

Медиана фактического CPU-времени / прогноза: 1,304 → 1,255. За пределы
0,5–1,5× вышли 25/361 и 12/330 заданий. Наборы выбранных заданий различаются,
поэтому это не сравнение ошибки на одинаковых входах. Остаточное расхождение
около 25% сохраняется. Разница между callback-интервалом и суммой CPU-фаз
имеет медиану 18 мкс в обоих вариантах; одни лишь эти неучтённые операции
не объясняют расхождение. Следующая проверка — прерывистая работа пула,
пробуждение workers и совпадающие формы внутри полного запроса.

В четырёх секундных пробах простоя счётчик CPU не вырос; это короткое измерение
с дискретностью Windows. `process_read_bytes` в JSON не равен физическому
SSD-трафику. Сравнения с рабочим GPU-only pack в этой серии нет.

## Корректность и воспроизведение

- Во всех трёх профилях GPU-проба побитно совпала с совместимым CPU-путём:
  720 случаев (80 × три формата × три числа потоков). Пропущенные CPU-строки
  сохранили начальные NaN, GPU их не перезаписал.
- Финальная сборка прошла 7/7 native CTest: cost, gpu_queue, lane, mmvq_fast,
  numerics и два экспертных контекста. Проверяются выбор с нулём CPU, бюджет,
  уникальные байты, конкуренция, GPU-стоимость, отсутствие будущих ID в решении,
  отказ от неполного/повторяющегося профиля и численная совместимость.
- Полная модель прошла строгие 8/8 greedy-сценариев против совместимого GPU-
  контроля, restore/lifecycle, cancel и seeded repeat. Выполнено 251 CPU-задание,
  428 строк. Seeded-запросы по прежней политике идут на GPU и не доказывают
  совместимость seeded CPU-арифметики.

Включение профиля сохраняет `STRATA_DS4_CPU_COST_PROFILE` и условия
[предыдущего отчёта](DEEPSEEK4_CPU_CALIBRATION.md). В v2 оба новых компонента
включены по умолчанию. Для раздельных опытов:

```text
STRATA_DS4_CPU_COST_CONTENTION=0  # использовать изолированные CPU/H2D-цены
STRATA_DS4_CPU_COST_GPU=0         # исключить GPU-арифметику и её перекрытие
```

CPU lane остаётся опциональным. Рабочий pack и Qwen не менялись. GPU-проба
использует непрерывное размещение весов, поэтому не оценивает отдельно
разбросанные адреса прямого GPU-кэша. Auto покрывает только измеренные формы
до четырёх CPU-строк; дополнительные геометрии и реальные Q8 fixtures остаются
открыты. Настройка дробления пула/spin/sleep и автоматическое пересоздание
профиля между сериями также ещё не реализованы.
