# Передача матриц без отдельного ожидания CPU перед каждой копией

12 октября 2026. Продолжение [прямого чтения GPU-кэша](DEEPSEEK4_DIRECT_CACHE.md).
На текущем профиле Q3 + DSpark сравнение B/A/A/B показало
**19,344 → 21,011 ток/с (+8,62%)** в поздних повторах и +8,31% по всем
прогретым повторам. Prefill практически не изменился.
Оптимизация включена в локальном `strata-deepseek4-ud-q3-k-xl-dspark.json`;
в общем случае runtime-флаг выключен. Сервер после проверок остановлен,
профиль будет применён при следующем запуске.

ПК: RTX 5090 32 ГиБ, Ryzen 9 9950X, RAM 128 ГиБ, Windows, CUDA 13.0.
Target: DeepSeek V4 Flash 0731 UD-Q3_K_XL на Samsung 990 PRO 4 ТБ (H:),
draft: DSpark Q8_0, `draft-max=2`. Target/draft GPU-кэши 15360/1024 МиБ,
staging и slabs 16 МиБ, контекст 8192, batch 4096, CPU threads 1.
Конвейер, частотный допуск, пакетный D2D и direct-cache=1 включены.
Численные эксперименты ATTENTION/PROJECTION и диагностика COST выключены.

## Что изменено

При одном scheduler copy штатный путь перед каждым выбранным weight-тензором
вызывал синхронизацию backend. На одном проходе DeepSeek это 129 отдельных
ожиданий CPU: gate/up/down для 43 слоёв. После появления прямого GPU-кэша
часть этих операций вообще не копирует матрицу в рабочий тензор.

`STRATA_DS4_ORDERED_EXPERTS=1` разрешает CPU готовить следующую передачу,
пока GPU заканчивает предыдущее вычисление. Порядок чтений и записей сохраняется
в CUDA stream: копии, публикация таблицы GPU-адресов и потребители идут
последовательно. Вспомогательные вычислительные streams присоединяются
к основному; direct-cache отдельно упорядочивает чтения перед освобождением
удержаний. Конвейер сохраняет events готовности H2D и повторного использования
слотов. Ожидание каждого **нового** набора expert ID остаётся обязательным.

Область применения ограничена NVIDIA, основным CUDA stream, одним scheduler
copy, выбранными host weights и коротким пакетом 1–8 токенов. Проверяются
обычный CUDA-буфер текущего устройства, contiguous weights без view,
IQ3_XXS/MXFP4/Q8_0, до 256 экспертов и поддерживаемые размеры матриц.
Нужны включённые expert pipeline и direct cache. Вне этих условий остаётся
прежнее ожидание. В частности, обычный большой prefill и scheduler с несколькими
copies используют прежний протокол зависимостей.

Изменение не добавляет предсказание экспертов и не меняет маршруты, веса,
ядра или решения кэша. Патч применяется к частной копии scheduler/CUDA backend;
Qwen и закреплённый `third_party` не изменены.

## Почему проверили этот участок

Добавлен `STRATA_DS4_SCHED_PROFILE=<путь.tsv>` и опция `--scheduler`
в `tools/profile_deepseek4_cost.py`. Диагностика измеряет время CPU внутри
существующих вызовов, сохраняет CUDA Graphs и не добавляет GPU-барьеры.
В обычных замерах скорости она выключена.

Для фиксированной истории ниже приведено среднее последних двух повторов.
Decode в каждой строке обрабатывает следующие 32 исторических токена после
prefix 36; это target-only диагностический прогон, без DSpark и sampling.

| Участок | Прежний путь, мс | Новый путь, мс |
|---|---:|---:|
| Scheduler, decode по одному токену | 1399,88 | 1283,80 |
| Ожидание перед weight-тензорами в этом decode | 1006,65 | 0 |
| Чтение ID вместе с ожиданием в этом decode | 54,36 | 752,01 |
| Scheduler, decode пакетами до трёх токенов | 900,26 | 812,74 |
| Ожидание перед weight-тензорами в этом decode | 582,61 | 0 |
| Чтение ID вместе с ожиданием в этом decode | 19,60 | 364,83 |

Большая часть ожидания **переместилась**, а не исчезла: чтение ID теперь
дожидается ранее поставленных вычислений. Эти времена не равны накладным
расходам синхронизации или времени чистой передачи D2H. Сокращение полного
времени проверено отдельно без профилировщика.

## Сравнение с предыдущим бинарником

Каждый процесс: prefill 4096, decode 32, четыре повтора decode с восстановлением
prompt из RAM-сессии, затем повторный полный prefill. Сам запрос decode содержит
36 токенов; это не генерация на контексте 4096. Файловый кэш ОС не очищался.

| Запуск в порядке измерения | Среднее repeat_3/4, ток/с | Среднее всех четырёх повторов, ток/с |
|---|---:|---:|
| B1, новый путь | 21,024 | 20,096 |
| A1, предыдущий бинарник | 19,380 | 18,560 |
| A2, предыдущий бинарник | 19,307 | 18,536 |
| B2, новый путь | 20,998 | 20,082 |
| Среднее A → B | **19,344 → 21,011 (+8,62%)** | **18,548 → 20,089 (+8,31%)** |

Повторный prefill: 8805,49 → 8774,68 мс (−0,35%). Выигрыш prefill не заявляется.
Все выходные token IDs и draft acceptance совпали. Решения кэша и объёмы
H2D/D2D также совпали: ускорение не получено уменьшением работы модели
или изменением объёма переданных весов.

Все 16 прогретых decode-запросов прочитали 0 байт H:. Первоначальный decode B1
прочитал 2977640448 байт; он исключён из сравнения скорости прогретого режима.
Счётчик относится ко всему физическому устройству. Во всех четырёх процессах
`cpu_compute_nodes=0`; максимальная наблюдавшаяся нагрузка процесса — 5,55%
общей мощности 32 логических CPU.

### Проверка на 128 выходных токенах

Отдельная пара B/A использовала финальный бинарник, тот же prompt 36 токенов,
prefill 4096 и по два прогретых повтора. A: 13,808 / 14,345 ток/с;
B: 14,745 / 15,684 ток/с. Среднее **14,076 → 15,215 ток/с (+8,09%)**.
Все output IDs и draft acceptance совпали; DSpark принял 78 из 98 черновых
токенов. Все четыре прогретых повтора прочитали 0 байт H:,
`cpu_compute_nodes=0`. Это подтверждает направление короткой серии,
но остаётся проверкой одного запроса, а не разных диалогов.

В этой паре полного prefill из RAM уже не получилось: заключительный prefill
прочитал 36,63 ГБ в A и 37,15 ГБ в B, заняв 91,63 и 93,71 с соответственно.
Поэтому его нельзя смешивать с prefill около 8,8 с из короткой серии.
Оптимизация короткого decode не устраняет повторное чтение весов с диска
при вытеснении страниц файлового кэша. Первый decode также читал SSD
(9,61/6,45 ГБ в A/B) и не входит в приведённую оценку прогретой скорости.

## Проверки и артефакты

Новый scheduler fixture проверяет три зависимые экспертные проекции с весами
в RAM, вычисляемые на GPU strided expert IDs, смену маршрутов и повтор графа.
Кэш 0/1/4 МиБ, пакеты 1/2/3/8/9, один и несколько scheduler copies, CUDA Graphs
включены и выключены: **720 побитовых сравнений**. В финальном прогоне прошли
**18/18 CTest**, включая direct-cache, transfer, GPU-only и speculative contracts.

Оба диагностических прогона сохранили все **184 пары полных logits/argmax**
предыдущего этапа: prefill 4096, decode по одному и до трёх токенов.
Это проверка сохранения существующей арифметики, не новое доказательство
равенства batch и serial режимов.

Финальная сборка прошла реальные проверки DSpark: **8/8 greedy-сценариев**
совпали с предыдущей сборкой с DSpark; сохранены восстановление и продолжение
сессий, отмена prefill/decode, восстановление после отмены и повторяемый
sampling с seed 123. Reference — DSpark предыдущего этапа, не serial target.

Локальные результаты в `bench/results`:

- `ds4-route-read-20261012-profile-{barrier,ordered}.json` и `.scheduler.tsv`;
- `ds4-route-read-20261012-profile-summary.json` — разложение времени и parity;
- `ds4-ordered-experts-20261012-{b1,a1,a2,b2}.json` и `.log`;
- `ds4-ordered-experts-20261012-summary.json` — сравнение четырёх запусков.
- `ds4-ordered-experts-20261012-long-{a,b,summary}.json` — проверка 128 токенов.
- `ds4-ordered-experts-20261012-validation.json` — сессии, отмена, seed и 8/8.

Для возврата прежнего порядка достаточно убрать `STRATA_DS4_ORDERED_EXPERTS`
из `env` профиля или поставить `0`, затем перезапустить движок. Пакетный D2D,
прямой GPU-кэш и DSpark от этого не отключаются.
