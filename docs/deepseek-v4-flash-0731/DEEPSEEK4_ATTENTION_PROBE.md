# Где расходятся пакетный и одиночный decode

10 октября 2026 года. Продолжение численной проверки из
[эксперимента MMVQ](DEEPSEEK4_MMVQ_TOKEN_BATCH.md).
Windows, Ryzen 9 9950X, RAM 128 ГиБ, RTX 5090 32607 МиБ, драйвер 581.80,
CUDA 13.0. DeepSeek V4 Flash 0731 UD-Q3_K_XL и DSpark Q8_0.
Перед серией свободно 106,08 ГиБ RAM, GPU занят на 1589 МиБ.

**Первое найденное расхождение находится внутри Flash Attention первого
слоя.** Его вход Q имеет нулевую разницу, а видимые текущему запросу K/V
и значения маски совпадают побайтно. Результат операции уже различается.
Это локализация одного источника численной зависимости от batch, не
доказательство, что остальные 42 слоя не имеют самостоятельных источников.

## Как проверяли

Добавлена отключённая по умолчанию диагностика
[activation_probe.hpp](../../backends/deepseek4/activation_probe.hpp).
Она подключается к `cb_eval` только при заданном пути результата.
Первые три verification-пакета запроса сравниваются с одиночным decode
тех же входных токенов из одного снимка target.

При сравнении учитываются реальные strides и ось токенов; повторяющиеся
имена различаются номером появления. Неподходящие формы явно отмечаются
как пропущенные. JSONL содержит форму, операцию, число отличающихся значений,
max/RMS, масштаб исходных значений и место максимального отклонения.
Для первого Flash Attention дополнительно сравниваются Q после всех
преобразований и **байты всех видимых K/V вместе с маской**, в порядке ключей.
Скрытые маской будущие ключи в это сравнение не входят.

Перед трассировкой выполняется контроль без чтения промежуточных тензоров;
такой контроль есть для batch и для каждого одиночного токена. Затем
восстанавливается исходное состояние и воспроизводится штатный пакет.
Его logits должны вернуться с максимальной разницей не выше 1e-5.

Параметры диагностики, передаваемые через `env` отдельного тестового профиля:

```text
STRATA_SPEC_TRACE_NODES=C:\work\git\my-repos\Strata\bench\results\trace.jsonl
STRATA_SPEC_TRACE_LAYER=0
STRATA_SPEC_TRACE_NODE=q-0,kv-0,@attention0,attn_raw-0,result_output
```

`TRACE_NODE` выбирает точные имена через запятую и имеет приоритет над
фильтром слоя. `@attention0` выбирает первый узел `FLASH_ATTN_EXT`, его
фактический Q, метаданные входов и видимые K/V. Эта специальная проверка
поддерживает одну последовательность, одну KV-голову и F16 K/V/маску.
Без списка имён фильтр слоя захватывает именованные активации слоя;
`TRACE_LAYER=-1` допускает все слои. Лимиты чтения проверяются до загрузки:
32 МиБ на обычный тензор, 64 МиБ на исходные K/V/маску и 256 МиБ на
сохраняемые данные фазы. Превышение завершает диагностический запрос ошибкой.
Файл дописывается; для независимых серий использованы разные пути.

Эта диагностика синхронизирует GPU и копирует активации на CPU для сравнения.
Она не используется для замеров скорости и отсутствует в рабочем профиле.
Вычисления самой модели остаются на GPU; во всех проверенных графах
`cpu_compute_nodes=0`.

## Почему подробной трассе нельзя доверять без контроля

Чтение всех именованных узлов первого слоя изменило итоговые logits:
максимальная разница с исполнением без чтения достигла 3,410206.
`cb_eval` разбивает граф и может препятствовать объединению операций CUDA.
Эти широкие трассы использованы только для выбора точек наблюдения.

Узкая трасса выше не изменила logits: разница instrumentation/control
равна **0 для batch и serial** во всех итоговых проверках. Replay тоже дал 0.
Первое расхождение подтверждено непосредственно на `FLASH_ATTN_EXT`,
до выходных преобразований и проекции attention.

## Штатное attention: результат

Context 8192, batch 4096, threads 1, GPU-кэши 15360/1024 МиБ,
DSpark2, shared scratch, stage 16, pipeline/auto, частоты 122880/32768.
MMVQ выключен. Тестовый prefill — 256 токенов; отдельный текстовый запрос
имеет 36 входных токенов, запрошено четыре выходных токена и повтор из RAM.
Это короткие диагностические запросы, не тест скорости длинного контекста.

Девять пакетов, **25 строк**, включая повторные. Во всех строках фактический
Q имеет разницу 0, видимые K/V и маска совпадают побайтно. Максимальная
разница выхода Flash Attention по всем строкам — 0,00131798.
Для первой строки отдельных пакетов:

| Позиция | Размер K, batch / serial | Видимых ключей | Max разницы attention | RMS |
|---|---|---:|---:|---:|
| 35 | 256 / 256 | 36 | 0,00000602007 | 0,000000273677 |
| 255 | 512 / 256 | 128 | 0,000218332 | 0,00000280788 |
| 256 | 512 / 512 | 128 | 0,000743508 | 0,00000512903 |
| 257 | 512 / 512 | 128 | 0,0000356436 | 0,000000387607 |

«Размер K» — число позиций в переданном ядру тензоре, включая закрытые
маской позиции. На границе 256 токенов пакет уже требует 512 позиций,
тогда как его первый одиночный токен ещё использует 256. Видимое окно
первого слоя при этом содержит те же 128 ключей.

В закреплённом CUDA-коде 512-wide GQA выбирает MMA-геометрию 1×8 для
одного query и 4×8 для трёх. Кроме того, число CUDA-блоков и разбиение K
в `launch_fattn` зависят от общего числа query и размера K.
Источники: [выбор ядра](../../third_party/llama.cpp/ggml/src/ggml-cuda/fattn.cu),
[распределение и объединение частичных результатов](../../third_party/llama.cpp/ggml/src/ggml-cuda/fattn-common.cuh).
Наблюдения показывают зависимость округлений от этих условий; точность
относительно независимого FP32/FP64-эталона в этом этапе не измерялась.

Максимальное расхождение **полных** logits в штатной серии — 3,09851;
смена argmax обнаружена в двух строках, представляющих один случай и
его повтор. Малую разницу первого слоя нельзя считать верхней границей
разницы всей сети: далее действуют квантование активаций, нелинейности и routing.

## Две проверенные модификации attention

Обе применялись только к копии CUDA-исходника DeepSeek в каталоге сборки.
Закреплённая зависимость не редактировалась.

1. Геометрия 1×8 для всего короткого пакета. На позициях 35/36 выход первого
   attention совпал с serial. На позициях 255–257 расхождение сохранилось;
   максимальная разница attention в серии выросла до 0,00358057.
   Геометрия не фиксирует распределение работы между CUDA-блоками.
2. Отдельный CUDA-запуск attention для каждого query с views входа, маски
   и выхода; остальные операции модели остаются пакетными. Совпали **20 из
   21** проверенных строк первого attention. Единственное отклонение — первая
   строка позиции 255, где размер K различается: max 0,000219584.
   На позициях 256/257 с одинаковым размером K разница стала 0.

Во втором варианте Q и видимые K/V/маска также совпали во всех строках;
эффект самой трассировки и replay равен 0. Включение вместе с экспериментальным
MMVQ дало тот же результат первого attention, но **не эквивалентность всей
модели**: максимальная разница logits осталась 3,61772 (без MMVQ — 3,60122).
Траектории генерации между режимами могут различаться; это результаты
внутренних сравнений batch/serial, не попарная оценка качества разных режимов.

Обе модификации исключены из рабочего исходника и итоговой сборки.
Настройки модели не изменены, ускорение по этим диагностическим запускам
не заявляется. Патч эксперимента и бинарник сохранены локально:
`build-local/deepseek4/activation-20261010/AttentionBatchPatches.cmake`
и `attention-experiment.exe`. SHA-256 экспериментального бинарника:
`ac34cc3a85c3778118fcc0f563feb0aa45cc262d0fb2733e765c83affa7e00a0`.

## Проверки и воспроизводимость

После удаления модификаций attention прошли **16 CTest**, включая проверку
сопоставления всех четырёх осей токенов, индекса ошибки, NaN и несовместимых
форм; **25 Python-тестов**. Итоговый бинарник SHA-256:
`e1e6eb95a8993acd7124bef35f8e92d87ecc0af34419d7c94ca54575bee74b51`.

На итоговой сборке повторно получены 25 строк с одинаковыми видимыми входами
attention и нулевым влиянием трассировки; token IDs совпали с контрольной
серией штатного ядра. Реальные A/B/A-сессии, продолжение, восстановление,
отмена prefill/decode, запрос после отмены и повтор с seed 123 прошли с DSpark
и без него. Отдельный `full_prefill_identical` остался false с DSpark и true
без него: диагностика эту ранее известную численную проблему не исправляет.
В 35 аудитах итоговой диагностической серии, 334 аудитах проверки DSpark
и одном аудите обычного decode вычислительных CPU-узлов нет.

В локальной сборке обнаружен неверно декодированный русский префикс MSVC
`/showIncludes`: у `main.cpp.obj` было 0 зависимостей, и правка заголовка
не вызывала пересборку. В локальном CMake-кэше исправлен префикс, сборка
переведена на code page 65001, main и тест пересобраны. Ninja теперь хранит
32 зависимости main, включая `activation_probe.hpp`; после изменения этого
заголовка `ninja -n` назначает пересборку main и теста. Изменения относятся
к локальному каталогу сборки, не к глобальным настройкам Windows.

Измерения до попадания расширенного probe в бинарник не использованы как
доказательство чтения дополнительных тензоров. Проверенные исходные данные:

- `bench/results/ds4-activation-20261010-visible0.jsonl` — штатное ядро,
  побайтовая проверка видимых входов;
- `ds4-activation-20261010-visible1.jsonl` — единая геометрия;
- `ds4-activation-20261010-serialfa-{0,2}.jsonl` — отдельные запуски attention,
  с выключенным и включённым MMVQ;
- `ds4-activation-20261010-final.{json,jsonl,log}` — контроль итоговой сборки;
- `ds4-activation-20261010-validate-{dspark,plain}.{json,log}` — сессии и отмена.

Все файлы последнего списка находятся в `bench/results`. Профили и команды
серий сохранены в `build-local/deepseek4/activation-20261010`.

## Что осталось

Изолированный GPU-тест на фиксированных Q/K/V/маске и независимый FP64-эталон
выполнены на следующем этапе: [результаты и эксперимент с уплотнением](DEEPSEEK4_ATTENTION_FIXTURE.md).
Первый attention теперь совпадает на проверенных запросах; следующий
локализованный участок — маршрутизируемый FFN первого слоя. Эксперимент
выключен в обычной сборке. Равенство полных logits не достигнуто; длинный
контекст и выигрыш скорости новой реализации ещё не проверены.
