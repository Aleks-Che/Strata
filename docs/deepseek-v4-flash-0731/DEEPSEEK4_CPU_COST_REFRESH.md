# Пересоздание CPU-профиля между запросами

Дата: 13 октября 2026. Продолжение этапа 4. Опциональный режим
`STRATA_DS4_CPU_COST_AUTO=1` обновляет стоимость CPU-вычисления по фактическим
запускам экспертов. Исходная калибровка v1–v3 по-прежнему обязательна и проверяется
по сборке, CPU, GPU, потокам, режиму пула, форматам и геометрии.

## Граница обновления

`Runner` открывает окно наблюдений после разбора запроса. В течение всего запроса
таблицы остаются постоянными, включая все speculative windows и DSpark. После
завершения запроса CUDA extension завершает кольца target и draft, CPU-service,
подкачку и отложенных GPU-потребителей. Только затем публикуется новая таблица.
Следующий запрос копирует её в существующий GPU-буфер; адреса CUDA Graphs сохраняются.

Обновление выполняется до ответа `DONE`. Время обслуживания включено в задержку
запроса и отдельно записывается в `STRATA_CPU_COST_REQUEST maintenance_us`.
Отмена, ошибка и запрос с явным seed сбрасывают накопленные наблюдения и серию
отклонений. Force-режим не обучает профиль. Переходы prefill/decode внутри запроса
не являются границей обновления. Длинный prefill остаётся на GPU.

## Когда меняется стоимость

Для каждой измеренной формы отдельно учитываются число токенов, гистограмма
повторений экспертов и наличие H2D. Профили с одинаковыми настройками разделяются
контекстами; другой формат, геометрия, GPU или число потоков получает свой профиль.

- Нужно минимум восемь измерений формы в каждом из двух последовательных успешных
  запросов. Хранятся последние 63 значения каждого запроса.
- Не менее 75% сохранённых измерений должны отклоняться в одну сторону:
  `факт/прогноз > 1,2` либо `< 0,8`. Единичный выброс не запускает обновление.
- Новая стоимость использует медиану. Шаг ограничен множителем 0,8–1,25;
  итог — 0,5–2 от исходной эффективной стоимости этой формы.
- Измерение при H2D меняет только loaded-стоимость и не снижает idle-оценку.
  Формы без достаточных измерений сохраняют прежние значения.
- GPU, PCIe, очередь, запас выигрыша и CPU-бюджет не переизмеряются этим механизмом.
  Их значения остаются из исходной калибровки.

Наблюдения не используют будущие маршруты. GPU-планировщик сохраняет прежние
ограничения: выбор по уже доступному префиксу, возможность выбрать ноль CPU-строк,
бюджет на токен и запас выигрыша. Неподходящая исходная калибровка оставляет auto
на GPU; динамические наблюдения не обходят проверку совместимости.

## Настройки и диагностика

```text
STRATA_DS4_CPU_MMVQ_FAST=1
STRATA_DS4_CPU_COST_PROFILE=<путь к совместимой offline-калибровке>
STRATA_DS4_CPU_COST_AUTO=1
STRATA_DS4_CPU_COST_AUTO_DIR=<необязательный каталог снимков>
```

Без `CPU_COST_AUTO` сохраняется прежний режим. Режим `CPU_COST_BURST` можно
использовать вместе с обновлением; его эффективные стоимости служат исходной точкой.

Если каталог указан, перед публикацией поколения записывается полный снимок
эффективных таблиц, идентичность исходной калибровки и номер запроса. Файл сначала
записывается во временное имя, затем переименовывается. Ошибка записи сохраняет
прежнюю таблицу и появляется в журнале; генерация не прерывается.

Снимки имеют тип `strata-cpu-runtime-cost`. Они предназначены для аудита и не
загружаются как offline-калибровка при следующем запуске. Новый процесс начинает
обучение от проверенного исходного профиля; исходный JSON не перезаписывается.
Без каталога обновление выполняется только в памяти. Каталог снимков накапливает
поколения; автоматического удаления истории нет.

`STRATA_CPU_COST_REFRESH` содержит номер запроса, профиль, поколение, число
обновлённых форм, число измерений и ошибку. В TSV добавлена колонка
`cost_generation`: по ней можно проверить фактическое применение новой таблицы.

## Проверки и ограничения

Нативный тест `deepseek4_cpu_cost_refresh` проверяет неизменность таблицы внутри
запроса, повторяемость отклонения, отмену/исключение, недостаточные выборки, выбросы,
пределы изменения, устаревшие поколения, раздельный idle/loaded, совместную запись
с двух service-потоков и сохранение старого профиля при ошибке записи.

Механизм обучается только на выбранных CPU-формах. Если CPU больше не выбирается,
новых наблюдений для этих форм не будет; принудительного пробного назначения нет.
Это адаптация CPU-оценки к текущему исполнению, а не повтор всей offline-калибровки
GPU/PCIe. Неизмеренные геометрии и реальные Q8-веса DSpark по-прежнему требуют
отдельной проверки. Полное сравнение CPU lane с рабочим GPU-only относится к этапу 5.

Артефакты этой проверки: `build-local/deepseek4/cpu-cost-refresh-20261013/`.

## Результаты на этом ПК

Windows, Ryzen 9 9950X, 128 ГиБ RAM, RTX 5090 32 ГиБ. Target UD-Q3_K_XL на H:,
DSpark Q8_0; 12 CPU-потоков, spin=0/parts=2, RAM-кэш 2 ГиБ, target GPU-кэш
15 ГиБ и draft 1 ГиБ. Совместимые AVX2/SwiGLU, GPU-очереди, CUDA Graphs и два
контекста включены. Исходный профиль v3 переснят для новой сборки за 118,81 с;
`CPU_COST_BURST=0`, чтобы проверить адаптацию непрерывной исходной оценки.

В каждом процессе шесть свежих запросов по 16 выходных токенов: четыре с prompt
372 токена, затем два с prompt 15 токенов. Первые два запроса исключены из таблицы
времени. Последовательность A/B/B/A, A — обновление выключено, B — включено с
записью снимков. Все 24 ответа совпали по token IDs между вариантами.

Среднее 30,2265 → 28,703 с, время ниже на 5,0%. Это одна короткая серия на двух
prompt, с различающимся состоянием файлового кэша; устойчивый выигрыш относительно
рабочего GPU-only здесь не установлен. Время загрузки модели и первые два запроса
в это сравнение не включены. `process_read_bytes` сохранён в сырых результатах;
это счётчик чтения процесса, а не доказательство физического чтения SSD.

В обоих B-прогонах после третьего запроса обновились по одной loaded-форме в двух
профилях. В запросах 1–3 использовалось поколение 0, в 4–6 — поколение 1.
Счётчики запросов сопоставлены с TSV; внутри запроса поколения не менялись.
Пересоздание двух таблиц с записью снимков заняло 2,704 и 2,847 мс, остальные
границы — 10–15 мкс по внутреннему таймеру пересчёта. Завершение очередей идёт
перед этим таймером; полная задержка границы входит в приведённое время запросов.

Для 124 и 121 задания поколения 1 найдены однозначно совпадающие формы в A.
На фактическом времени каждого такого задания сравнены прежний и новый прогноз:
медиана `abs(факт/прогноз−1)` — 27,35% → 16,04% и 26,71% → 13,09%.
Это сравнение ошибок на тех же измерениях, без подмены ускорением CPU-ядра.
