# Выходные проекции attention: фиксированный MMQ

11 октября 2026. RTX 5090 32 ГиБ, Ryzen 9950X, 128 ГиБ RAM, Windows,
CUDA 13.0, драйвер 581.80. Target: DeepSeek V4 Flash 0731 UD-Q3_K_XL
на H:. Закреплённый llama.cpp: `3cf03257f219afbe7334045ff7c6a06ac68c627d`.

Продолжение [Q_b и длинного attention](DEEPSEEK4_QUERY_EXPANSION.md).
Фиксированная арифметика устранила различия обеих выходных проекций
первого attention на двух проверяемых исторических позициях. Полные logits
модели всё ещё различаются; первый выбранный токен полного и поэтапного
prefill теперь тоже различается. Это численный эксперимент, не исправление
всей модели и не подтверждённая оптимизация рабочего профиля.

## Что изменено

В исследовательском `STRATA_DS4_PROJECTION_MMQ` добавлены два режима:

- `4`: прежний режим 3 для Q/K/Q_b плюс групповая `attn_output_a`,
  Q8_0, форма **4096×1024×8**.
- `5`: режим 4 плюс `attn_output_b`, Q8_0, форма **8192×4096**.

Используется существующий приватный MMQ с фиксированным разбиением K.
Проверены J8/1, J32/1, J64/1, J32/4 и J64/4. Для модельных проверок
сохранён общий **J64/4**; у Q_b остаётся одна часть K, как на предыдущем этапе.
Дополнительного преобразования весов или переноса вычислений на CPU нет.

Для wo_a разрешены contiguous вход и фактический layout модели:
перестановка `[K,groups,tokens]` в `[K,tokens,groups]`. Квантователь входа MMQ
уже учитывает эти strides, поэтому дополнительное копирование не требуется.
Группы не объединяются в одну матрицу; каждая использует свои веса.
Ограничения по имени, Q8_0, точной форме, NVIDIA Ampere+, batch 1–4096,
contiguous весам и выходу сохраняются. Неподдержанные случаи идут штатным путём.
Изменение действует только при `STRATA_DEEPSEEK_PROJECTION_EXPERIMENT=ON`.

Исходники: [dispatch](../../backends/deepseek4/projection_dispatch.inc),
[фиксированный MMQ](../../backends/deepseek4/ProjectionMmqPatches.cmake),
[трасса сетки](../../backends/deepseek4/projection_grid_trace.hpp),
[тест wo_a](../../backends/deepseek4/test_output_projection.cpp),
[тест плотных проекций](../../backends/deepseek4/test_projection_batch.cpp).

## Изолированные GPU-проверки

У wo_a проверены обе раскладки и batch
1/2/3/4/5/8/9/16/32/128/371/409/1024/4096: **28 сочетаний**.
В каждом сравниваются выбранные строки с одиночным GPU-расчётом и независимым
FP64-эталоном из сохранённых квантованных весов. Максимальная ошибка
фиксированного варианта относительно FP64 — **0,04672092** на этих данных,
при заданном до запуска допуске 0,05. Все выбранные batch/serial результаты
фиксированного пути совпали побитово. Это не оценка ошибки всей модели.

Общий prefix 371/409 проверяется целиком, по всем восьми группам:

| Проекция | Число сравниваемых значений | Различаются штатно | Max Δ штатно | Различаются с фиксированным MMQ |
|---|---:|---:|---:|---:|
| wo_a | 3039232 | 2260760 | 6,67572e-6 | **0** |
| wo_b | 1519616 | 1298503 | 1,04904e-5 | **0** |

Обновлённый тест плотных проекций содержит **67 сочетаний и 36 защитных
проверок**. Для wo_b максимальная ошибка относительно FP64 — **0,05968414**
при допуске 0,08, выбранном для её большей длины K. В тесте wo_a дополнительно
проверяются неподходящие имя/форма/тип/layout, batch 4097 и изоляция групп:
обнуление одной группы одного токена не должно менять остальные результаты.

## Проверка на модели

Прежние 410 token IDs: полный prefix 409 против prefix 371, одиночных
371–403 и пакета 404–408; токен 409 вычисляется отдельно в обоих случаях.
FA=4, HCA=1, router=1, TF32 off. Позиция 282 сравнивается внутри пакетов
409 и 371, позиция 371 — внутри пакета 409 и при одиночном вычислении.

| Позиция / max Δ | Контроль MMQ=3 | Только wo_a, MMQ=4 | wo_a + wo_b, MMQ=5 |
|---|---:|---:|---:|
| 282: вход wo_a | 0 | 0 | 0 |
| 282: выход wo_a | 1,01328e-6 | **0** | **0** |
| 282: выход wo_b | 2,14577e-6 | 1,66893e-6 | **0** |
| 371: вход wo_a | 0 | 0 | 0 |
| 371: выход wo_a | 0,000505690 | **0** | **0** |
| 371: выход wo_b | 0,006469503 | 0,000542760 | **0** |

После исправления только wo_a вход wo_b стал одинаковым, а её выход остался
разным. Это отдельно подтверждает расхождение wo_b. Совместное включение
даёт ноль на обеих позициях. Текущий токен 409 также имеет точные проекции
и выход первого слоя, но исторический выход слоя 0 ещё различается:
max Δ **1,78814e-7** у позиции 282 и **0,022314711** у позиции 371.

| Режим | Max Δ конечных logits | RMS Δ | Argmax full / segmented |
|---|---:|---:|---|
| Контроль MMQ=3 | 3,321738720 | 0,682308695 | 1 / 1 |
| Только wo_a | 3,191519737 | 0,649678277 | 539 / 1 |
| wo_a + wo_b | 2,995472074 | 0,571712750 | 112496 / 1 |

Уменьшение max/RMS не означает улучшения качества: в этой истории
**greedy-выбор полного и поэтапного prefill перестал совпадать**.
Контроль MMQ=3 повторён на том же итоговом exe и точно воспроизвёл прежние
числа. Итоговый MMQ=5 повторил результат более раннего архива `ob.exe`.
Все восемь прогонов сохранили нулевое влияние observer, snapshot/restore
и replay на logits. Время диагностических прогонов со чтением активаций
не используется для оценки скорости inference.

## Следующая доказанная граница

Дополнительная трасса позиции 371 выделила матрицу
`blk.0.hc_attn_fn.weight`, F32 **16384×24**. Нормализованный вход совпадает
побитово, но 15 из 24 выходов различаются, max Δ **0,00006103515625**,
даже при TF32 off. Коэффициенты HC вычисляются отдельной веткой до attention;
расхождение проявляется в смешивании после него:

| Узел | Max Δ |
|---|---:|
| HC pre / вход attention | 0 |
| HC post coefficients | 1,49012e-8 |
| HC combination coefficients | 7,45058e-9 |
| Результат HC после attention | 1,78814e-7 |
| HC перед FFN | 1,19209e-7 |
| Нормализованный вход FFN | 7,15256e-7 |
| Выход routed MoE | 0,044727404 |
| Выход shared expert | 0,001514375 |

Top-k IDs роутера на этой позиции совпадают, веса — нет. Вход FFN уже
различается, поэтому приписывать всё расхождение самому MoE или роутеру
по этой трассе нельзя. Следующий шаг — изолировать F32-проекции коэффициентов
HC с неизменным порядком редукции, затем заново сравнить вход и выход FFN.
Этот этап ещё не реализован; полное равенство prefill остаётся открытым.

Сырые результаты: `bench/results/ds4-output-projection-20261011-*`.

## Проверки сессий и DSpark

Итоговая экспериментальная сборка прошла **25/25 CTest за 94,56 с**.
Тест wo_a содержит **12 защитных проверок**, включая новый batch 4097;
тест плотных проекций с обычным TF32 также прошёл 67 сочетаний и 36 защитных
проверок. Подбор пяти разбиений выше выполнялся с TF32 off.

Проверки модели без DSpark и с ним прошли за **92,62 / 89,65 с**.
Все greedy token IDs совпали между этими двумя режимами в восьми сценариях:
две сессии, восстановление, продолжение активной и восстановленной сессии,
полный prefill продолжения, один токен и генерация после отмены.
Отдельно проверены отмена prefill/decode и воспроизводимость фиксированного seed.
**30 проверок причинности DSpark дали max Δ logits = 0**.
Аудит графа: 1 запись без DSpark и 360 с ним, везде `cpu_compute_nodes=0`.

В обеих проверках `full_prefill_identical=true`: все 16 token IDs продолжения
совпали после полного, поэтапного и восстановленного prefill. Этот тест
формирует продолжение из ответа текущего движка; фиксированная история
численного probe сохранена с предыдущего этапа. Поэтому результаты относятся
к разным последовательностям токенов. Совпадение этого продолжения не отменяет
различий logits и argmax на фиксированной истории выше. Качество на корпусе,
Linux и другие видеокарты не проверялись.

## Скорость и ресурсы

A/B/B/A на одном итоговом `final.exe` без DSpark. Контроль — MMQ=3,
кандидат — MMQ=5; в обоих FA=4, HCA=1, router=1, TF32 off, J64/4,
MMVQ=2, контекст 8192, batch 4096, expert-кэш 15360 МиБ, staging 16 МиБ.
Это сравнение двух исследовательских режимов, а не рабочего профиля.
Decode — медиана двух прогретых повторов по 32 токена. Повторный prefill
4096 очищает состояние сессии, сохраняя кэш весов; файловый кэш ОС не очищался.

| Порядок | Режим | Прогретый decode, ток/с | Повторный prefill 4096, мс | Физическое чтение H: в прогретых фазах |
|---|---|---:|---:|---:|
| A1 | Контроль | 17,805 | 9810,80 | 0 |
| B1 | wo_a + wo_b | 17,341 | 10051,20 | 0 |
| B2 | wo_a + wo_b | 17,333 | 10531,10 | 0 |
| A2 | Контроль | 18,462 | 9518,24 | 0 |

Медианы запусков: **18,134 → 17,337 ток/с (−4,39%)** и
**9664,52 → 10291,15 мс (+6,48%)**. Ускорение не подтверждено.
Все повторы внутри одного режима дают одинаковые token IDs, но ответы A/B
начинают различаться с 26-го токена из 32. Поэтому decode включает изменение
маршрутов экспертов: эти числа описывают режимы на одном запросе и не выделяют
чистую стоимость двух проекций. У полного prefill одинаковы все 4096 входных
token IDs и три выходных token IDs; его время измерено до decode.

Во всех восьми прогретых повторах decode и четырёх повторных prefill счётчик
`PhysicalDrive6` показал **0 байт чтения**. Первые запросы читали диск;
счётчик относится ко всему устройству, а не только к движку.
Медианы CPU процесса на активных фазах A1/B1/B2/A2:
**3,95 / 4,86 / 5,18 / 5,26%** всей системы; максимумы:
**5,50 / 5,75 / 6,28 / 5,90%**. Максимальный общий CPU в этих запусках:
14,2 / 17,6 / 21,9 / 28,9%. Внешние приложения не останавливались.
Выборочные пики общей VRAM по `nvidia-smi`:
**28703 / 28728 / 28847 / 28402 МиБ**. Это память всей видеокарты;
набор из четырёх запусков не задаёт точный предел памяти backend.
Вычислительный GPU-аудит всех запусков содержит 0 CPU-узлов;
копирование и управление графом по-прежнему требуют CPU.
