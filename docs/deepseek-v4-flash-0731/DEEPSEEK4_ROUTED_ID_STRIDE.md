# Routed MMQ: раскладка ID и совпадение DSpark

11 октября 2026 года. RTX 5090 32 ГиБ, Ryzen 9 9950X, RAM 128 ГиБ,
Windows, CUDA 13.0, драйвер 581.80; DeepSeek V4 Flash 0731 UD-Q3_K_XL,
DSpark Q8_0. Модель находится на H:, Samsung 990 PRO, PhysicalDrive6.

**Исправлена регрессия экспериментального короткого MMQ.** Он выбирал разные
пути вычисления для одиночного токена и verification-пакета, начиная со слоя 3.
После исправления точно совпали все 319 проверенных строк logits;
DSpark и обычный greedy совпали в 8/8 сценариев вместо 4/8.
Ускорения нет: A/B/B/A дал **20,973 → 19,534 ток/с**, −6,86%.
Этот численный режим остаётся выключенным в рабочем профиле.

Продолжение [предыдущей проверки routed MoE](DEEPSEEK4_ROUTED_MMQ.md).
Числа ниже относятся к исследовательским профилям с ранее добавленными
численными режимами. Это не сравнение с рабочей сборкой, где эксперименты OFF.

## Причина

В первых трёх слоях используются ID из таблицы по входному токену.
Начиная со слоя 3, top-k представляет собой view `[6,N]` внутри полного
argsort `[256,N]`. Реальная раскладка ID:

| | Форма | Strides, байт |
|---|---|---|
| Verification | `[6,3,1,1]` | `[4,1024,3072,3072]` |
| Одиночный токен | `[6,1,1,1]` | `[4,1024,1024,1024]` |

Предикат `strata_routed_mmq_tensor` требовал `ggml_is_contiguous(ids)`.
При `N=1` stride между колонками не используется, поэтому проверка проходила.
При `N=3` тот же view отклонялся. Одиночный decode получал MMQ, пакет — MMVQ.
Для MXFP4 на Blackwell это меняло также квантование активаций: FP4 против Q8.

Трасса первого пакета на позиции 371 показала точное совпадение выходов
слоёв 0–2, входа слоя 3, Q/K, attention, router, ID и весов маршрутов.
В варианте без fusion первая разница возникла в routed gate/up:

| Узел слоя 3, строка 0 | max Δ до исправления |
|---|---:|
| Gate IQ3 | 0,0003920496 |
| Up IQ3 | 0,0004038513 |
| Down MXFP4 | 0,0874727070 |
| Routed MoE | 0,0584658831 |
| Выход слоя | 0,0321500823 |

Входы gate/up и выбранные ID совпадали. Observer и replay дали ноль.
Отдельная трасса выходов слоёв с обычным fusion подтвердила ту же границу.

## Исправление и тест

В `backends/deepseek4/routed_mmq.hpp` разрешён stride между колонками ID,
который уже поддерживает штатный MMQ: его ID helper читает `nb[1]` явно.
Проверяются I32, шаг 4 байта внутри колонки, шесть ID, соответствие числа
токенов, отсутствие дополнительных измерений и допустимый шаг колонки.
Ограничения на типы/размеры матриц, именованные experts, GPU и 1–8 токенов
сохранены. Дополнительного копирования ID и нового CUDA-ядра нет.

`test_routed_mmq.cpp` дополнен 36 GPU-сценариями: три формы матриц,
IQ3/MXFP4, N=1/2/3/4/8/9. У одинаковых входов сравниваются плотные ID
и view с шагом **1024 байта**, как у реальной модели.
До исправления провалились **24/36** новых случаев, прежние 54 матричных
случая, 30 ограничений dispatch и три полные цепочки прошли.
После исправления прошли все **123** случая, включая новые 36.
N=9 сохраняет прежний dispatch. Существующая проверка разреженного входа
матрицы также продолжает требовать прежний путь.

Прошли **5/5 выбранных CTest за 49,16 с**: routed MMQ, speculative contract,
prefill probe, activation probe и запрет CPU-вычислений графа.

## Проверка всей модели

Сравниваются все 129280 logits каждой позиции verification-пакета с
одиночным исполнением **тех же входных token IDs из одного snapshot**.
Затем snapshot и исходный пакет восстанавливаются; replay проверяется отдельно.
Эти диагностические прогоны не используются для измерения скорости.

| Режим | Пакеты / строки | max Δ logits | Смен argmax, все строки | Из них использованные строки greedy |
|---|---:|---:|---:|---:|
| Routed MMQ=0 | 106 / 315 | 0 | 0 | 0 |
| IQ3, до исправления | 100 / 297 | 2,9674435 | 3 | 3 |
| IQ3+MXFP4, до исправления | 104 / 309 | 6,7880621 | 19 | 9 |
| IQ3+MXFP4, после исправления | **107 / 319** | **0** | **0** | **0** |

Число строк различается из-за принятия draft и траектории генерации;
внутри каждого сравнения входы одинаковы. Таблица включает также seeded
sampling, поэтому 15 использованных строк со сменой argmax до исправления
не равны девяти строкам именно greedy. Отброшенные строки draft не влияют
на текущий ответ. Replay во всех пакетах равен нулю.

В первом исправленном пакете точно совпали наблюдаемые выходы всех **43 слоёв**
и конечные logits всех трёх позиций с обычным fusion. Подробная трасса слоя 3
без fusion также дала ноль. В обоих случаях влияние observer равно нулю.

Полные проверки сессий, A/B/A, продолжения, восстановления, отмены prefill/decode,
повтора после отмены, single-token и seeded repeat прошли. Все восемь greedy
сценариев совпали с отдельным прогоном без DSpark, включая одинаковые входы.
Диагностика не изменила десять завершённых ответов контрольного DSpark-прогона.
**30 проверок причинности** дали нулевую разницу anchor logits.
Это результаты данного набора запросов, не доказательство для любого контекста.

## Скорость и ресурсы

Один `fixed.exe`, порядок **A/B/B/A**. A — routed=0, B — исправленный routed=2.
Остальные численные режимы одинаковы: FA=4, HCA=1, router=1,
TF32 override=0, projection MMQ=5/J64/splits4, HC=3, router sample=3, shared=2.
Fusion обычный; serial/activation-диагностика выключена.

Контекст 8192, batch 4096, один поток управления, target/draft expert cache
15360/1024 МиБ, DSpark2, shared scratch, stage16, pipeline1/readers2/auto,
frequency/match-size, CRT, early refill=0, prefill hits=1, slabs16, MMVQ2.
В каждом процессе: prefill 4096, отдельный запрос 36 токенов с decode 32,
четыре повтора из RAM-сессии, ещё один полный prefill 4096.

| Запуск | Медиана повторов 3–4, ток/с | Все четыре, ток/с | Прогретый prefill, мс |
|---|---:|---:|---:|
| A1 | 20,712 | 19,008 | 9755,11 |
| B1 | 19,562 | 18,156 | 9700,51 |
| B2 | 19,506 | 18,181 | 9623,22 |
| A2 | 21,234 | 19,527 | 9665,34 |
| Медианы A → B | **20,973 → 19,534** | **19,267 → 18,168** | **9710,225 → 9661,865** |

Поздние повторы медленнее на **6,86%**, все четыре — на **5,70%**.
Разница prefill −0,50% при двух измерениях каждого режима не считается
подтверждённым ускорением. A принимает 18/26 draft-токенов, B — 18/27.
Повторяемость token IDs внутри каждого режима проверена; смена арифметики
между режимами меняет ответы с 26-го токена, поэтому сравнение включает разные
маршруты. Выходные ID после полного prefill между A/B также различаются.

Все **16 прогретых decode и четыре полных прогретых prefill**:
PhysicalDrive6 — **0 байт / 0 операций чтения**. Кэш ОС не очищался.
Медианы CPU процесса — 4,07–4,72% всего 32-поточного CPU, максимум 5,89%;
общий CPU в выборках достигал 10,7%. Пик VRAM — **30560 МиБ**;
опрос раз в две секунды может пропускать короткие пики.
Во всех **3194** записях аудита моделей `cpu_compute_nodes=0`.

## Оставшееся расхождение prefill

`full_prefill_identical=false` и без DSpark, и с ним. Для прежних фиксированных
410 token IDs полный префикс 409 сравнивался с 371 + одиночные шаги + пакет
404–408; последний токен 409 в обоих случаях вычислялся отдельно.
Fusion выключен для чтения внутренних узлов.

На исторической позиции 371 вход слоя 2, HC, текущие Q/K совпадают точно.
Среди **221 видимого ключа attention** различаются 19 позиций:
59 значений K и 59 значений V, max Δ **0,0009765625**. Маски, sinks и
индексы видимых позиций одинаковы. Первое наблюдаемое расхождение выхода
attention — **0,0001022816**; выход слоя 2 — **0,0030410960**.
Слой 3 уже получает разные входы.

Конечные logits полного/поэтапного prefill различаются на **4,0255194**,
RMS **0,7729465**, argmax в этом probe совпал: 539/539.
Все observer/restore/replay-контроли равны нулю.
Следующий участок — происхождение различающихся исторических K/V слоя 2,
включая compressor и предшествующие токены. Равенство Q/K выбранной позиции
не доказывает равенство всей истории.

Продолжение: [проекции компрессора](DEEPSEEK4_COMPRESSOR_PROJECTIONS.md).
На той же истории удалось устранить различия сжатого K/V и получить
точное совпадение всех конечных logits полного/поэтапного prefill.

## Повторение диагностики

В `main.cpp` добавлены `STRATA_SPEC_SERIAL_REPORT=<jsonl>` и
`STRATA_SPEC_CHECK_ROUNDS=1..64` (по умолчанию 3). JSONL содержит входные ID,
позицию/строку, argmax и оценки обоих победителей, max/RMS, использованные
выходы и replay. Отчёт включается явно; обычная генерация его не создаёт.

`tools/validate_deepseek4_speculative.py` сохраняет входные ID и принимает
`--check-serial --serial-rounds 64`. `--greedy-reference <baseline.json>`
делает совпадение восьми greedy-сценариев обязательной проверкой.
Контроль deadline теперь также находит архивный исполняемый файл по его пути.

```powershell
.venv/Scripts/python.exe tools/validate_deepseek4_speculative.py `
  --config build-local/deepseek4/spec-rows-20261011/fixed-dspark.json `
  --tokens 32 --check-serial --serial-rounds 64 `
  --greedy-reference bench/results/ds4-spec-rows-20261011-fixed-plain.json `
  --output bench/results/ds4-spec-rows-repeat.json
```

Выходной `.serial.jsonl` должен быть новым. Код проверки reference дополнительно
проверен на сохранённых результатах: старое расхождение обнаруживает 4/8,
исправленный прогон — 8/8. Команда выше объединяет эти проверки в одном запуске.

Сырые результаты: `bench/results/ds4-spec-rows-20261011-*`.
Профили, token IDs, команды и архивные executables:
`build-local/deepseek4/spec-rows-20261011`.
