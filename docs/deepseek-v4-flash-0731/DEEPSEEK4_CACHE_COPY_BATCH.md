# Пакетное копирование матриц из GPU-кэша

Принято для локального рабочего профиля: финальная A/B/B/A-серия дала
**17,697 → 18,883 ток/с, +6,70%**, при одинаковых выходных токенах и
draft acceptance. Prefill 4096 не ускорился. Параметр включён в
`strata-deepseek4-ud-q3-k-xl-dspark.json`; новый запуск использует его
автоматически. Общий default движка остаётся выключенным.

Измерения 11 октября 2026: RTX 5090 32 ГиБ, Ryzen 9 9950X,
128 ГиБ RAM, Windows, CUDA 13.0, DeepSeek V4 Flash 0731 UD-Q3_K_XL.
Модель хранится на H: (Samsung 990 PRO 4 ТБ). Target-кэш — 15360 МиБ,
staging — 16 МиБ, frequency admission, match-size и асинхронный конвейер.

## Что показала диагностика

Добавлен `--expert-transport` в `tools/profile_deepseek4_cost.py`.
Вместе с `--events` он записывает отдельную таблицу `.transport.tsv`:
H2D в кольцо, D2D из кольца, D2D из кэша и суммы CPU-времени чтения
и ожиданий. Нужна сборка с `STRATA_DEEPSEEK_COST_EXPERIMENT=ON`;
CUDA graphs для такой диагностики отключены.

Фиксированная история: prefill 4096 и отдельные проходы с префиксом 36
и следующими 32 токенами, по одному или по три. Повторы используют
одинаковые token IDs; KV между проходами очищается, экспертный кэш остаётся.
Ниже медиана повторов 1–3, первый прогрев исключён.

| Измерение за 32 токена | По одному | По три |
|---|---:|---:|
| D2D из кэша, МиБ | 80959,7 | 59646,1 |
| Число отдельных D2D из кэша | 23282 | 17154 |
| Сумма событий D2D из кэша, мс | 439,53 | 421,14 |
| H2D, МиБ | 7229,5 | 6729,5 |
| Сумма событий H2D, мс | 529,54 | 493,88 |
| Сумма событий D2D из кольца, мс | 40,67 | 41,84 |
| CPU-чтение, мс | 332,40 | 308,76 |
| CPU-ожидание готового слота потребителем, мс | 136,40 | 139,24 |
| CPU-ожидание освобождения слота читателем, мс | 12,41 | 43,37 |
| Полное время decode с наблюдением, мс | 3171,47 | 1628,87 |

Суммы нельзя складывать в полное время: H2D, CPU-чтение и вычисления
перекрываются. CUDA events включают паузы между host submissions;
их влияние существенно при десятках тысяч небольших операций.
Это диагностические времена, не оценка обычной скорости генерации.
Все 184 пары контрольных сумм полных logits и argmax совпали с прежним
фиксированным проходом без наблюдения.

## Реализация

Режим `STRATA_DS4_CACHE_COPY_BATCH=1` собирает до 32 копирований
из экспертного GPU-кэша в один CUDA kernel с 16-байтовыми переносами.
Вычислительные MMVQ/MMQ-ядра, квантованные данные, маршруты экспертов
и арифметика модели сохраняются. В длинном prefill остаётся прежний путь.

Очередь завершается перед запуском потребителя, перед загрузкой нового
payload, вытеснением или переиспользованием cache allocation и при
завершении плана. Поэтому отложенное чтение не переживает свою матрицу.
При динамическом кэше сохраняются существующие межпоточные reuse fences.
Дескрипторы передаются по значению в аргументах запуска: дополнительной
таблицы указателей в GPU-памяти и асинхронного чтения временного host-массива нет.

Соседние эксперты имеют перекрывающиеся 512-байтовые MMQ-хвосты.
Перед пакетным запуском конец предыдущего диапазона обрезается по началу
следующего; последняя запись сохраняет хвост. Это исключает гонку блоков,
сохраняя исходную семантику копирования. Неупорядоченные адреса разделяются
на разные запуски; невыровненные адреса и длины используют обычный D2D.

Это материализация рабочего тензора пакетами. Прямое чтение матричными
ядрами из GPU-кэша здесь ещё не реализовано; D2D-байты в основном остаются.

## Проверки

Шесть вариантов `deepseek4_expert_transfer` с включённым новым режимом
прошли побайтовые проверки: fixed arena, pipeline, prefill cache hits,
AVX2/early refill, slabs 16 и 1 МиБ. Проверяются вытеснение, фрагментация,
общий бюджет target/draft, давление памяти, возврат бюджета и отмена плана.

Fixture дополнен 70 матрицами, чтобы пересечь две границы пакета из 32
дескрипторов. Проверяются соседние хвосты, обратный порядок и повтор одного
адреса, невыровненные матрицы, чтение результата после явного flush до
finish. Отдельный CTest `deepseek4_expert_transfer_batch` включает новый
режим вместе с pipeline, prefill cache hits и slabs.

Проверка DSpark с пакетным копированием прошла: 8/8 greedy-сценариев,
98 verification-пакетов / 286 строк logits с максимальной абсолютной
разницей 0, 29 проверок причинности с разницей 0. Восстановление и
продолжение сессий, отмена prefill/decode и воспроизводимость seeded
sampling также прошли. В этой проверке используются точные экспериментальные
проекции; её результаты нельзя выдавать за batch/serial-паритет обычного
численного режима.

Новый флаг `--expert-transport` отдельно проверен на входе из 68 токенов:
получены H2D, ring/cache D2D, `cache_batch_d2d` и host wait/read записи.
Все 180 контрольных пар logits/argmax независимых decode-проходов совпали
с исходным фиксированным прогоном. Его времена не участвуют в сравнении
скорости, поскольку история прогрева экспертного кэша отличается.

В паре проходов полной модели без CUDA events совпали все 184 пары
контрольных сумм/argmax, token IDs и счётчики экспертных передач.
Медианы трёх прогретых повторов:

| Фиксированная работа | Обычные D2D, мс | Пакет, мс |
|---|---:|---:|
| Prefill 4096 | 8328,27 | 8312,61 |
| 32 токена по одному | 1994,52 | 1874,25 |
| 32 токена по три | 1243,35 | 1173,71 |

Это численный эксперимент с прежним набором точных проекций и attention.
Его абсолютную скорость нельзя переносить на рабочий профиль.

## DSpark в численном эксперименте

Q8_0 DSpark, draft-max=2, draft-кэш 1024 МиБ, общий scratch. Четыре
процесса в порядке A/B/B/A, в каждом четыре повторных decode по 32 токена
и один полный prefill 4096. CUDA events выключены.

| Режим | Поздние прогретые decode, ток/с | Все четыре повторных decode, ток/с | Prefill 4096, мс |
|---|---:|---:|---:|
| Обычные D2D | 14,849 | 14,011 | 8992,55 |
| Пакетное копирование | 15,590 | 14,654 | 8979,95 |
| Изменение | +4,99% | +4,59% | −0,14% времени |

«Поздние» — медиана repeat_3/repeat_4 внутри каждого процесса, затем
медиана двух процессов. Выходные token IDs и draft acceptance совпали
во всех 20 повторных запросах; все они прошли с нулевым физическим чтением
PhysicalDrive6 (счётчик всего устройства). Максимум CPU процесса по
периодическим замерам — 5,50% от 32 логических CPU; общий максимум VRAM —
31210 МиБ. 956 записей GPU-аудита указали `cpu_compute_nodes=0`.

## Рабочий профиль, обычная сборка

Все три CMake-эксперимента ATTENTION, PROJECTION и COST выключены.
Меняется только `env.STRATA_DS4_CACHE_COPY_BATCH`: `0` против `1`.
Протокол A/B/B/A тот же, четыре повтора decode и один prefill на процесс.

| Режим, финальная сборка | Поздние прогретые decode, ток/с | Все четыре повторных decode, ток/с | Prefill 4096, мс |
|---|---:|---:|---:|
| Обычные D2D | 17,697 | 17,019 | 8690,385 |
| Пакетное копирование | 18,883 | 18,124 | 8684,095 |
| Изменение | +6,70% | +6,49% | −0,07% времени |

Первая серия обычной сборки дала 17,718 → 18,951 ток/с (+6,96%).
После добавления явного выбора CUDA-устройства перед отложенным запуском
повторена вся A/B/B/A-серия; в таблице приведена именно финальная версия.
Результаты разных executable не объединялись.

В каждой серии совпали выходные token IDs и draft acceptance всех 20
повторных запросов. В первой было 15/20 запросов без физических чтений H:,
максимум остальных — 851968 байт. В финальной — 8/20 без чтений, максимум
13523968 байт. Счётчик относится ко всему устройству, а не только движку:
эта серия не доказывает полностью свободный от SSD режим. Более ранняя
серия численного эксперимента выше имела нулевые чтения во всех 20 запросах.

Финальный максимум CPU процесса по периодическим замерам — 5,90% от 32
логических CPU, общий максимум VRAM — 30725 МиБ. 896 записей GPU-аудита
имели `cpu_compute_nodes=0`. CPU обслуживает загрузку и протокол, вычисления
модели сохраняются на GPU. Ускорение измерено на повторении выбранного
запроса; оно не гарантирует тот же процент на другом тексте или холодном старте.

Обычная сборка прошла 14 контрольных CTest, все 237 прежних контрольных
сумм attention сохранены. После явного выбора устройства повторно прошли
восемь проверок передач и GPU-only. На нескольких GPU и на Linux этот режим
не проверялся. Qwen и закреплённые исходники `third_party` этим этапом не менялись.

Итоговая настройка локального JSON:

```json
"env": {
  "STRATA_DS4_CACHE_COPY_BATCH": "1"
}
```

Для отключения достаточно `0` или удаления этого ключа и перезапуска.
Копия исходного профиля сохранена как `original-profile.json` в каталоге этапа.
В 20:40 все тестовые движки остановлены; сервер на 8080 не запущен.
Проверка состояния — `final-state.json`.

SHA-256 обычного executable:
`fa9de0c579011bc5edce519d356c3c10a0d9483ac55e09c3a83d4c406bf38bdd`.
SHA-256 нового рабочего профиля:
`e68843865164a302df6662870d895f7a8da902256fb25658f6d5dd68646c7a17`.

Следующий отдельный кандидат — прямое чтение MMVQ/MMQ из GPU-кэша.
Для него нужны таблицы адресов матриц и удержание cache allocations до
завершения матричного ядра, включая fusion, CUDA graphs и межпоточное
переиспользование. Текущий результат не измеряет потенциальную пользу
такого пути и не даёт оснований обещать его процент ускорения.
