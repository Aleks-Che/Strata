# DeepSeek: этапы attention и пустые sparse-блоки

Дата: 11 октября 2026. ПК: RTX 5090 32 ГиБ, Ryzen 9950X,
128 ГиБ RAM, Windows, CUDA 13.0, driver 581.80.
Модель: DeepSeek-V4-Flash-0731 UD-Q3_K_XL; GPU-only forward.

Продолжение [замеров стоимости операций](DEEPSEEK4_KERNEL_COST.md).
Задача — найти дорогую часть private stable attention, сохранив
совпадение пакетного и последовательного вычисления.

## Раздельные CUDA-события

В диагностической сборке COST_EXPERIMENT добавлена трасса трёх участков:
подготовка sparse-списков, MMA-ядро и stream-K fixup. События ставятся
в поток запуска; сбор результатов выполняется на границе scheduler
subgraph. Между этими тремя участками дополнительных синхронизаций нет.

Ограничения прежние: CUDA graphs выключены, события могут включать
ожидание потока и задержки запуска на CPU. Эти числа не заменяют
скорость обычной генерации. Полные 4096 токенов разбиваются на порции
по 128 запросов. На каждом prefill записано 4128 этапов: 43 слоя,
32 порции, три этапа.

Медиана суммы событий из повторов 1–3, миллисекунды:

| Нагрузка | Подготовка списков | MMA | Fixup |
|---|---:|---:|---:|
| Prefill 4096 | 23,112 | 2336,527 | 258,584 |
| Следующие 32 токена по одному | 7,824 | 39,595 | 6,270 |
| Следующие 32 токена порциями по три | 3,251 | 31,626 | 2,590 |

У коротких проходов независимый префикс из 36 токенов, KV между
проходами очищается; кэш экспертов сохраняется. Для сравнения используется
полный экспериментальный набор численных режимов из предыдущего отчёта,
без DSpark, cache 15360 МиБ, stage 16 МиБ, batch 4096, context 8192.

184 пары FNV-1a всех конечных logits и argmax совпали с предыдущим
неинструментированным контрольным прогоном. Профилировщик не изменил
результат этой нагрузки. Основное время приходится на MMA, поэтому
следующая гипотеза касается работы внутри этого ядра.

Запуск:

```powershell
python tools/profile_deepseek4_cost.py --config TARGET_ONLY.json --tokens-json TOKENS.json --events --attention-stages --output bench/results/FRESH_NAME.json
```

Нужны сборки ATTENTION_EXPERIMENT и COST_EXPERIMENT, режим
`STRATA_DS4_FA_COMPACT=4`; для полного численного набора также
PROJECTION_EXPERIMENT. Трасса этапов записывается в `FRESH_NAME.attention.tsv`.
Проверяются новые пути результатов и явное включение событий.

## Гипотеза: не вычислять пустые хвостовые блоки

Stable stream-K сохраняет одно и то же разбиение K для каждого query.
Консервативная граница HCA включает резерв под сжатые ключи, поэтому
часть блоков не содержит видимых строк. Исходное ядро всё равно
выполняет последнюю итерацию MMA для такой пустой части.

Эксперимент `STRATA_DS4_FA_SKIP_EMPTY=1` сохраняет сетку блоков,
разбиение непустых частей, softmax и порядок fixup. Для полностью
пустой хвостовой части он записывает нулевой частичный результат
и соответствующие max/rowsum. Последний блок отвечает за attention
sink: его вклад требуется даже при отсутствии видимых K/V.

Первая версия, пропускавшая этот вклад, отклонена: 67 из 76 проверок
не прошли. Её времена не являются результатом корректной оптимизации.

## Полная модель без событий

Фиксированные token IDs, четыре повтора, независимые KV-проходы,
DSpark выключен. Медианы повторов 1–3:

| Нагрузка | Исходный, мс | Пропуск пустых, мс |
|---|---:|---:|
| Prefill 4096 | 11006,374 | 9051,042 |
| 32 следующих токена по одному | 2192,969 | 2171,777 |
| 32 следующих токена порциями по три | 1369,806 | 1349,882 |

Все 184 пары FNV/argmax совпали. Совпали также счётчики экспертов:
190526 hits, 21232 misses, 125402 bypass, 5299 evictions,
492732587520 байт H2D, 1222859275264 байт D2D. Это сравнение одного
и того же вычисления с одинаковыми маршрутами экспертов.

Следующая серия использует DSpark Q8_0, draft-max=2, общий scratch,
1024 МиБ draft cache. Обычные fusion и CUDA graphs, без событий.
Каждый процесс: четыре повтора генерации по 32 токена с RAM-сессией
и один полный prefill 4096 в новой сессии.

| Запуск | Поздние повторы 3/4, ток/с | Все четыре, ток/с | Prefill 4096, мс |
|---|---:|---:|---:|
| A1 | 13,665 | 12,936 | 11646,30 |
| B1 | 13,656 | 12,890 | 9742,49 |
| B2 | 13,795 | 12,999 | 9883,02 |
| A2 | 13,654 | 12,926 | 11719,30 |

Медианы A/B: **11682,80 → 9812,755 мс prefill (−16,01% времени)**.
Decode: **13,659 → 13,725 ток/с (+0,48%)** по поздним повторам,
12,931 → 12,944 по всем четырём (+0,10%). Такой разброс не подтверждает
ускорение decode. Output IDs совпали во всех сравниваемых запросах;
acceptance тоже: 18/26 на коротком запросе и 1/6 после длинного prefill.

7 из 20 повторных запросов не читали H:; остальные дали от 128 КиБ
до 13,03 МиБ физического чтения всего диска. Источник этих чтений
не установлен; серия не называется RAM-only. В 956 сообщениях аудита
CPU forward nodes равны нулю. Максимальный CPU процесса — 5,33%
от всех 32 логических процессоров, системный — 15,2%; минимум доступной
RAM 56,96 ГиБ, наблюдаемый максимум общей VRAM 31642 МиБ.

Оптимизация оставлена как opt-in часть ATTENTION_EXPERIMENT с
`STRATA_DS4_FA_SKIP_EMPTY=1`. Она ускоряет длинный prefill точного
экспериментального набора. Это не измерение выигрыша над рабочим
профилем; его настройки и обычная сборка сохраняются.

Проверка полного DSpark с этим флагом прошла: 8/8 greedy-сценариев
совпали с сохранённым target-only эталоном из проверки индексатора.
В 98 verification-пакетах все 286 строк logits совпали с последовательным
вычислением, replay тоже точный; 29 проверок причинности дали нулевую
разницу. Пройдены RAM restore, продолжение активной сессии, полный
повторный prefill, отмена prefill и decode, следующий запрос после отмены
и повтор seeded sampling. Эти диагностические времена не включены в A/B/B/A.
