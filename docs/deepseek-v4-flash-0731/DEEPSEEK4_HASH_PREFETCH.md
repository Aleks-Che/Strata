# Ранняя подгрузка первых трёх hash-слоёв

12 октября 2026. Проверены два варианта ранней подгрузки на текущем профиле
Q3 + DSpark. По всем прогретым повторам получены **+0,22%** и **+0,13%**.
Заметное ускорение не подтверждено: оба режима оставлены выключенными
в рабочем профиле. Код доступен для дальнейших экспериментов.

ПК: RTX 5090 32 ГиБ, Ryzen 9 9950X, RAM 128 ГиБ, Windows, CUDA 13.0.
Target: DeepSeek V4 Flash 0731 UD-Q3_K_XL на Samsung 990 PRO 4 ТБ (H:).
Draft: DSpark Q8_0, `draft-max=2`. Target/draft GPU-кэши 15360/1024 МиБ,
staging/slabs 16 МиБ, контекст 8192, batch 4096, CPU threads 1.
Pipeline, frequency admission, пакетный D2D, direct-cache=1 и
ordered-experts=1 включены. ATTENTION/PROJECTION/COST выключены.

## Реализация

В первых трёх слоях target expert ID зависят от входного token ID и постоянной
таблицы `ffn_gate_tid2eid`. Их можно получить до вычисления attention.
Это точный табличный lookup, без предсказания маршрутов. В локальном DSpark
`hash_layer_count=0`, поэтому ранняя подгрузка его не затрагивает.

В начале каждого исполнения графа scheduler находит до трёх последовательных
hash-групп. Он читает исходные входные token IDs, разрешая scheduler copies,
и выполняет один маленький CUDA lookup по тем же GPU-таблицам. Вычисления
модели остаются на GPU; CPU составляет списки адресов для передачи.
Добавляется 768 байт GPU scratch и 768 байт pinned RAM на активный backend.

Первый план запускается перед постановкой основного графа. Следующий — после
постановки последнего экспертного потребителя предыдущей группы, когда GPU
ещё может выполнять его и последующие операции. Прочитанные веса поступают
в существующее кольцо H2D. Рабочие тензоры не записываются заранее:
их заполнение остаётся на штатной границе scheduler с CUDA dependencies.

При достижении обычной точки загрузки движок сохраняет раннюю очередь,
если адреса, размеры и cacheable-флаги срезов совпали. Иначе очередь отменяется
и строится штатный план. В каждый момент активен один план слоя, поэтому
не резервируются сразу матрицы всех трёх слоёв. Выход из графа, ошибка и отмена
завершают producer до освобождения model mappings. Direct-cache leases
освобождаются после постановки потребителя и регистрации его reader fences.

Runtime-флаг `STRATA_DS4_HASH_PREFETCH`:

- не задан или `0`: прежний путь;
- `1`: ранняя подгрузка, затем обычное чтение expert ID с GPU;
- `2`: та же подгрузка с повторным использованием точных ранних ID.
  Повторное чтение трёх hash-маршрутов не требуется: основной граф читает
  ту же неизменяемую GPU-таблицу с теми же входными токенами.

Оба режима требуют pipeline, direct-cache и ordered-experts, один scheduler
copy и отсутствие callback evaluation. Поддержаны короткие пакеты 1–8 токенов,
contiguous I32 GET_ROWS и таблицы weights без view на том же NVIDIA GPU,
до восьми ID на токен и до 256 экспертов. Проверяются диапазоны token/expert ID.
Большой prefill, learned routing и неподходящие layouts остаются на обычном пути.
В режиме 2 неизменённый граф продолжает вычислять hash-маршруты; убрано только
повторное ожидание и чтение их результата на CPU.

Это не предсказатель следующих 40 слоёв и не вычисление cache-hit экспертов
параллельно ожиданию misses. Квантование, порядок арифметики и число экспертов
не меняются. Изменения находятся в отдельном DeepSeek backend и частных
CMake-патчах; Qwen и закреплённый `third_party` не изменены.

## Измерения

Две независимые серии B/A/A/B относительно прежнего рабочего бинарника.
Каждый процесс: prefill 4096, затем короткий запрос с prefix **36 токенов**,
decode 32 и четыре повтора с восстановлением prompt из RAM-сессии.
Первая серия дополнительно выполняла полный prefill после decode; во второй
этот повтор исключён. Это не замер генерации на контексте 4096. Файловый кэш
ОС не очищался. В замерах скорости профилировщик выключен.

| Режим и запуск | Среднее repeat_3/4, ток/с | Все четыре повтора, ток/с |
|---|---:|---:|
| Режим 1, B1 | 20,600 | 19,689 |
| Режим 1, A1 | 20,558 | 19,545 |
| Режим 1, A2 | 21,002 | 19,995 |
| Режим 1, B2 | 21,179 | 19,938 |
| Среднее A → B | **20,780 → 20,889 (+0,53%)** | **19,770 → 19,813 (+0,22%)** |
| Режим 2, B1 | 20,878 | 19,953 |
| Режим 2, A1 | 21,129 | 20,168 |
| Режим 2, A2 | 20,766 | 19,897 |
| Режим 2, B2 | 21,093 | 20,166 |
| Среднее A → B | **20,948 → 20,985 (+0,18%)** | **20,033 → 20,059 (+0,13%)** |

В каждой серии все output token IDs и draft acceptance совпали. Совпали
cache hits/misses, bypass/evictions, H2D/D2D, число групп и chunks конвейера;
unused и fallbacks равны нулю. Все **32 прогретых decode** прочитали **0 байт H:**.
На каждый warm decode принято 19 из 24 предложенных draft-токенов.

Первые запросы и повторные полные prefill имели разное состояние файлового
кэша. Например, в первой серии повторный prefill прочитал 48,8–49,3 млрд байт
в трёх процессах и 0,291 млрд в четвёртом. Они не используются как доказательство
ускорения. Ранний lookup отключён для большого prefill, и выигрыш длинного
контекста здесь не заявляется.

Новые режимы не уменьшают объём необходимых передач и затрагивают только
три слоя из 43. Добавляются ранний lookup и подготовка планов. Эти факторы
могут ограничивать выигрыш, но отдельный вклад каждого в этих сериях не измерен.

## Проверки

- В каждом режиме 184 пары полной контрольной суммы logits FNV1a64 и argmax
  точно совпали с предыдущим бинарником на фиксированных входах.
  Workload: четыре повторения prefill 4096, decode по одному и до трёх токенов.
- В каждом таком прогоне: 172 ранних lookup, 516 планов, 516 использований
  без перезапуска, 0 несовпадений, 0 unused chunks и 0 pipeline fallbacks.
  H2D/D2D и решения кэша совпали с эталоном.
- В режиме 2 профиль scheduler подтверждает 40 обычных чтений маршрутов
  и три использования ранних ID на короткий проход вместо 43 обычных чтений.
  В начале прохода добавляется один ранний CUDA lookup с ожиданием результата.
- Синтетический scheduler-тест: по 480 побитных сравнений с CUDA Graphs
  и без них, всего 960. Два режима, входные токены на CPU/GPU,
  последовательные/параллельные copies, кэши 0/1/4 МиБ, batch 1/2/3/8/9,
  смена токенов, три hash-слоя и девять матриц. Проверяются фактическое включение,
  fallback, диапазоны ID, несовпавший и брошенный ранний план.
- Все 20 выбранных CTest прошли: hash-prefetch, ordered-experts, direct-cache,
  transfer, GPU-only contract и speculative state. Внешний флаг режима 2
  также включён при проверке прежних learned-routing тестов.
- Реальная проверка режима 2 с DSpark: 8/8 greedy-сценариев совпали
  с предыдущим движком. Прошли восстановление RAM-сессии, продолжение,
  отмена prefill/decode, следующий запрос после отмены и повтор seed 123.
  В этом процессе: 207 ранних планов и 207 использований, без несовпадений,
  unused chunks или pipeline fallbacks; DSpark не запускает hash-prefetch.
- GPU-only audit во всех прогонах: `cpu_compute_nodes=0`.
  Максимальная нагрузка процесса в двух сериях скорости — 5,99%,
  нормированная на 32 логических CPU. Это I/O, копирование и управление,
  а не выполнение матриц модели на CPU.
