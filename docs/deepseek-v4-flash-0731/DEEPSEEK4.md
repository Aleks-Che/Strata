# DeepSeek V4 Flash 0731 в Strata

Все материалы модели собраны в [оглавлении](README.md). Подтверждённые результаты
и рабочие настройки на 11 октября 2026 года — в
[сводке удачных оптимизаций](DEEPSEEK4_SUCCESSFUL_OPTIMIZATIONS.md).

Добавлен отдельный C++ backend `strata-deepseek4`. Он выполняет граф DeepSeek V4 из
llama.cpp, закреплённого на `3cf03257f219afbe7334045ff7c6a06ac68c627d`, и использует
протокол сервера Strata. Проверено 3 октября 2026 года на Windows, Ryzen 9 9950X,
128 ГиБ RAM, RTX 5090 32 ГиБ и Samsung 990 Pro.

Qwen3.8-Flash-Next продолжает работать через прежний `engine/strata.exe`. Его сборка,
профиль `strata-q8_0.json`, веса, MTP и кэш экспертов не заменяются. Сборка DeepSeek
находится в отдельном каталоге `build-deepseek4`.

## Почему нужен отдельный backend

Значения ниже прочитаны из локальных GGUF, а не выведены из названий файлов.

| Свойство | Qwen3.8-Flash-Next | DeepSeek-V4-Flash-0731 |
|---|---:|---:|
| `general.architecture` | `qwen4exp` | `deepseek4` |
| Слои | 48 | 43 |
| Размер скрытого состояния | 2560 | 4096 |
| Эксперты на слой | 512 | 256 |
| Выбранные эксперты | 10 | 6 |
| Предтокенизатор | `qwen35` | `joyai-llm` |

У DeepSeek другие attention и compressor states, hash routing первых трёх слоёв,
hyper-connections с Sinkhorn и формат инструментов DSML. Размеры и операции
специализированного пути Qwen к этой модели неприменимы.

Локальная модель: `H:\deepseek-v4-flash-0731\UD-Q8_K_XL`, пять частей GGUF,
1328 тензоров. Первая часть содержит метаданные и токенизатор, без тензоров.
Размер весов — 161 864 270 172 байта, примерно 150,75 ГиБ:

- routed experts: 137,0625 ГиБ, **MXFP4**;
- остальные тензоры: примерно 13,69 ГиБ, преимущественно **BF16**;
- таблицы hash routing — I32, нормы и другие малые тензоры — F32.

Название `UD-Q8_K_XL` не означает, что каждый тензор закодирован Q8_K.
Полная копия всех весов в RAM не создаётся.

Также проверена `UD-Q3_K_XL`: четыре части, те же 1328 тензоров, 119,40 ГиБ весов.
В ней 64,3125 ГиБ IQ3_XXS и 47,8125 ГиБ MXFP4; остальные веса преимущественно Q8_0.
Сравнение реальных запусков и условия измерения — в
[DEEPSEEK4_BENCHMARKS.md](DEEPSEEK4_BENCHMARKS.md).
Последующее ускорение Q3 до 12,19 токена/с на прогретом повторе описано в
[DEEPSEEK4_EXPERT_STREAMING.md](DEEPSEEK4_EXPERT_STREAMING.md).

## Память и вычисления

Все вычисления графа, включая routed experts, выполняются на GPU. Плотные веса,
embedding и состояния attention размещаются в VRAM. Веса холодных экспертов хранятся
в отображённых GGUF; scheduler переносит на GPU только экспертов, выбранных router
для текущего batch. Холодные страницы читает Windows/Linux по мере обращения.
CPU repacking и предварительная загрузка всего файла отключены.

Обычный GGML offload host-backed операций начинается с batch 32. Backend задаёт
`GGML_OP_OFFLOAD_MIN_BATCH=1` до инициализации CUDA, чтобы decode одного токена тоже
считал экспертов на GPU. Наличие весов в host mmap означает место хранения, а не
CPU-инференс. CPU обслуживает ввод, токенизацию, sampling, маршрутизацию копирования
и файловую память; нулевая загрузка всего CPU не ожидается.

Перед каждым исполнением графа проверяются назначения **всех** вычислительных узлов.
Если хотя бы один назначен CPU, запрос завершается ошибкой до выполнения графа.
Views и узлы без операции не считаются вычислениями. В журнале проверенного запуска:
`STRATA_GPU_AUDIT ... cpu_compute_nodes=0 expert_matmuls_gpu=129`.
Отсутствие GPU или неполный offload dense-слоёв также вызывает ошибку.

Изменение prefetch и проверка scheduler применяются CMake к копиям исходников
в каталоге сборки. Закреплённая зависимость и сборка Qwen не редактируются.

`--gpu-expert-layers N` размещает routed experts последних N слоёв на GPU.
Для этого файла один слой занимает 3,1875 ГиБ. Это фиксированное размещение слоёв.
Дополнительно доступен `--expert-cache-mib` — GPU LRU отдельных матриц экспертов
из разных слоёв, и `--expert-stage-mib` — размер каждого из двух pinned-буферов
передачи. Политика resident budget и адаптации специализированного пути Qwen
остаётся самостоятельной.

Для сравнительных замеров доступны три независимые опции:
`--expert-host-copy crt|avx2` (по умолчанию `crt`),
`--expert-early-refill 0|1` и `--expert-prefill-cache-hits 0|1` (обе выключены).
AVX2 и раннее заполнение требуют `--expert-pipeline 1`; AVX2 также требует
поддержки CPU/ОС. Последняя опция использует уже готовые матрицы GPU-кэша при
prefill больше восьми токенов, без добавления новых записей и обучения частот.
Опции применяются к target и DSpark; их также принимает `setup_deepseek4.py`.
Условия и результаты A/B — в [отчёте](DEEPSEEK4_TRANSFER_TRIALS.md).

`STRATA_DS4_CACHE_COPY_BATCH=1` объединяет копирования выбранных матриц
из GPU-кэша в пакеты до 32 дескрипторов для decode до восьми токенов.
Задаётся в `env` профиля JSON, действует после перезапуска, по умолчанию
выключен. Требует новой обычной сборки, но не CMake-экспериментов.
Поддерживает fixed arena и динамический кэш; численная математика не меняется.
Это ускорение материализации рабочего тензора.
[Проверки и замеры](DEEPSEEK4_CACHE_COPY_BATCH.md).

`STRATA_DS4_DIRECT_CACHE=1` позволяет короткому MMVQ читать попадания в GPU-кэш
непосредственно, без материализации. Поддержаны IQ3_XXS, MXFP4 и Q8_0;
промахи, prefill/MMQ и неподдерживаемые формы используют прежний путь.
Нужна сборка с `STRATA_DEEPSEEK_DIRECT_CACHE_EXPERIMENT=ON` (default OFF).
Таблица адресов обновляется при CUDA Graph replay, матрицы защищены от
вытеснения до постановки чтений потребителя. На RTX 5090 B/A/A/B дал
18,266 → 18,601 ток/с (+1,84%); полные logits сохранились.
[Ограничения и проверки](DEEPSEEK4_DIRECT_CACHE.md).

Периоды затухания истории при политике `frequency` настраиваются отдельно:
`--expert-frequency-decay` и `--draft-expert-frequency-decay` (0..1000000000).
Единицы — обращения к матрицам, не токены. По умолчанию оба 0: прежняя формула
`max(4096, cache_bytes >> 17)`. Период закрепляется при создании backend;
перезапуск применяет новое значение. Большой prefill не обучает частоты.
[Замеры и ограничения подбора](DEEPSEEK4_STAGE_AND_DECAY.md).

`--mmvq-token-batch 0|1|2` — экспериментальный запуск короткого MMVQ-пакета
с арифметикой одиночного токена. Режим 1 применяется к routed матрицам,
2 — также к dense; default 0 сохраняет штатные ядра. Проверенный путь ограничен
NVIDIA, IQ3_XXS/MXFP4/Q8_0 и 2–4 токенами. Опция не ускорила проверенную
генерацию DeepSeek и в рабочем профиле выключена.
[Матричные проверки, численные ограничения и замеры](DEEPSEEK4_MMVQ_TOKEN_BATCH.md).

Для исследования batch/serial доступна отключённая по умолчанию трассировка
промежуточных активаций через `STRATA_SPEC_TRACE_NODES`. Она измеряет собственное
влияние на logits и сравнивает видимые входы первого Flash Attention.
Параметры, ограничения и результаты — в [отчёте](DEEPSEEK4_ATTENTION_PROBE.md).
Для замеров скорости этот режим не используется.

Изолированный тест `deepseek4_attention_batch_test` проверяет CUDA attention
по скалярному FP64-эталону, включая batch, padding и разреженные маски.
Эксперимент с уплотнением ключей собирается отдельно через
`STRATA_DEEPSEEK_ATTENTION_EXPERIMENT=ON` (default OFF); рабочего ускорения
пока не даёт. [Результаты и команды](DEEPSEEK4_ATTENTION_FIXTURE.md).

`STRATA_DS4_ROUTER_MMVF=1` — отдельный эксперимент для BF16 router 4096×256
с batch 2–4: сохраняет F32-активации и арифметику одиночного токена.
Без переменной используется штатный dispatch. [Проверки и ограничения](DEEPSEEK4_ROUTER_MMVF.md).

`STRATA_DS4_HCA_COMPACT=1` — экспериментальное уплотнение видимых ключей HCA.
Требует сборки с `STRATA_DEEPSEEK_ATTENTION_EXPERIMENT=ON`; при
`STRATA_DS4_FA_COMPACT=1`, `2` либо `3` действует для batch ≤4,
при режиме `4` — до 4096 с временными группами по 128 queries.
Обычная сборка его не включает.
[Проверки коротких запросов и контекста 4096](DEEPSEEK4_HCA_COMPACT.md).

`STRATA_DS4_FA_COMPACT=3` сохраняет разбиение stream-K одиночного query
в общем запуске короткого batch на NVIDIA Ada и новее. Неравномерная
сетка использует отдельные query. Режим 2 остаётся численным контролем.
[Реализация, замеры и ограничения](DEEPSEEK4_STABLE_STREAM_K.md).

Для оставшегося расхождения полного prefill и продолжения добавлен отдельный
`tools/probe_deepseek4_prefill.py`: сравнение фиксированных token IDs без
DSpark, с контролем влияния snapshot/restore и чтения активаций. По умолчанию
диагностика выключена. [Результаты и запуск](DEEPSEEK4_PREFILL_PARITY.md).
Проверка [HC и Q/K от 11 октября](DEEPSEEK4_PROJECTION_PARITY.md) выделила
TF32 и различия квантования входов. Отдельные матрицы стали ближе между
batch/serial, но конечные logits всё ещё различаются. Новый эксперимент
`STRATA_DEEPSEEK_PROJECTION_EXPERIMENT` выключен в обычной сборке.
Его [вариант с фиксированным MMQ](DEEPSEEK4_FIXED_PROJECTION_MMQ.md)
обеспечил точный исторический K/V первого слоя на проверенной истории,
но не равенство всей модели или подтверждённое ускорение.
Следующее [расширение Q_b и длинного attention](DEEPSEEK4_QUERY_EXPANSION.md)
даёт точный результат первого attention для двух исторических токенов.
Полное равенство prefill ещё не достигнуто; режимы остаются исследовательскими.
В этом же этапе исправлен отказ роста динамического кэша после освобождения
VRAM под Windows: контроллер и проверка допуска матриц используют глобальное
измерение NVML. Исправление действует и при выключенных экспериментах.

Продолжение [выходных проекций wo_a/wo_b](DEEPSEEK4_OUTPUT_PROJECTIONS.md)
устранило их различия на двух исторических позициях. Полные logits и первый
greedy-токен полного/поэтапного prefill на фиксированной истории ещё различаются.
Следующая выделенная граница — F32-матрица коэффициентов HC при одинаковом входе.
Режимы MMQ=4/5 остаются за экспериментальной CMake-опцией.
Следующий [эксперимент HC](DEEPSEEK4_HC_PROJECTIONS.md) использует штатный MMVF
для F32-коэффициентов с группами по 1/4/8 токенов. На проверенных исторических
позициях точно совпал вход FFN первого слоя; конечные logits ещё различаются.
`STRATA_DS4_HC_MMVF` доступен только в экспериментальной сборке, default OFF.
Там же добавлен [router для длинного prefill](DEEPSEEK4_ROUTER_LONG_PREFILL.md):
`STRATA_DS4_ROUTER_SAMPLE_MMVF=1/2/3`, группы 1/4/8. Он устраняет проверенное
расхождение router и весов маршрутов, но shared/routed expert ещё различаются.
Рабочий профиль этим численным экспериментом не заменяется.

Следующая [проверка shared expert](DEEPSEEK4_SHARED_PROJECTIONS.md) выделила
независимые различия gate/up и down. `STRATA_DS4_SHARED_MMQ=1/2` включает
фиксированный MMQ и учитывает обход однотокенного fusion. На проверенных
позициях shared-ветка совпала; на токене 282 совпал весь наблюдаемый первый
слой. На токене 371 различается routed MoE, полного равенства logits нет.
Режим доступен только в экспериментальной сборке, по умолчанию выключен.

В [этапе routed MoE](DEEPSEEK4_ROUTED_MMQ.md) добавлена выборочная
трассировка `@expert:` с входами и ID. `STRATA_DS4_ROUTED_MMQ=1/2`
проверяет штатный MMQ на коротких пакетах IQ3 / IQ3+MXFP4. В диагностике
без fusion совпал наблюдаемый первый слой, но полного равенства logits нет.
Сравнение DSpark с обычным greedy выявило регрессию; режим оставлен
исследовательским, за той же CMake-опцией, по умолчанию выключен.

В [следующем этапе исправлена проверка stride ID](DEEPSEEK4_ROUTED_ID_STRIDE.md):
top-k view со слоя 3 больше не переключает пакет на другой путь относительно
одиночного токена. Точно совпали 319 строк logits, а DSpark/greedy — 8/8
сценариев. A/B/B/A дал **20,973 → 19,534 ток/с**; режим остаётся выключенным.
Для полного/поэтапного prefill следующая найденная граница — отличающиеся
исторические K/V attention слоя 2 при одинаковых текущих Q/K.

[Проекции компрессора](DEEPSEEK4_COMPRESSOR_PROJECTIONS.md) закрыли эту
границу на фиксированной истории 410 токенов: режим проекций 6 добавляет
CSA/HCA/indexer KV и gate. Конечные logits полного/поэтапного prefill
совпали точно, как и выходы всех 43 слоёв на двух исторических позициях.
Эксперимент требует отдельной сборки; рабочий профиль не переключён.

[Проверка 3072 токенов](DEEPSEEK4_LONG_PREFILL_AUDIT.md) выявила следующую
границу: одну различающуюся историческую запись HCA слоя 7, при одинаковых
текущих Q/K. На том этапе равенства prefill на этой истории не было. В прямом
A/B/B/A весь численный набор дал **14,500 против 17,606 ток/с** рабочего
профиля; prefill 4096 — **10976,65 против 8721,905 мс**. Поэтому рабочие
настройки сохранены. Диагностический инструмент теперь допускает до
4096 токенов с проверкой границ batch и контекста.

[Проекции индексатора](DEEPSEEK4_INDEXER_PROJECTIONS.md) устранили это
расхождение: на позиции 2347 слой 6 выбирал один другой ключ из 512.
Экспериментальный `STRATA_DS4_INDEXER_PROJECTION=1` фиксирует порядок
суммирования Q_b и весов голов индексатора. На той же истории 3072 токена
конечные logits полного/поэтапного prefill теперь совпадают точно.
Диагностика допускает ограниченное окно из 128 исторических токенов.
Рабочий профиль по-прежнему не переключён на численный эксперимент.

[Профиль стоимости операций](DEEPSEEK4_KERNEL_COST.md) выделил attention
как основной источник дополнительных затрат этого эксперимента.
`STRATA_DEEPSEEK_COST_EXPERIMENT=ON` собирает отключаемую диагностику
CUDA events; `tools/profile_deepseek4_cost.py` сравнивает фиксированные
входные token IDs без сэмплирования. Диагностика требует отключения
CUDA graphs и не используется для измерения обычной скорости генерации.
Проверенные изменения размера порций и объединения stream-K не дали
устойчивого ускорения и удалены; все три CMake-эксперимента оставлены OFF.

Кнопка с шестерёнкой справа сверху открывает [настройки GPU-памяти](../VRAM_SETTINGS.md).
Для DeepSeek CUDA можно менять лимит матриц или целевую общую занятость VRAM во
время работы. Движок освобождает кеш при нехватке свободной видеопамяти и наполняет
его по мере запросов, когда память снова доступна. Фиксированные веса и состояния
контекста этой настройкой не выгружаются.

`--expert-slab-mib 0..256` задаёт размер блоков динамического кэша;
0 сохраняет отдельные CUDA allocations. При 16 несколько матриц одинакового
размера делят блок до 16 МиБ. Пустые блоки освобождаются; контроллер учитывает
и незанятые слоты. Фиксированная арена не меняется, опция сама не включает
динамический режим. [Устройство и проверки](DEEPSEEK4_DYNAMIC_SLABS.md).

На Windows доступен необязательный `--working-set-mib`: предел физического working
set процесса. По умолчанию 0 — управление у ОС. Это не предел virtual memory и не
резерв свободной RAM от других приложений. Ошибка применения лимита останавливает
запуск. Для основного профиля ограничение выключено. Архивы сессий не создаются,
если не проходят проверку свободной RAM и commit.

GPU-only устраняет CPU-математику, но не ожидание SSD и передачу весов по PCIe.
Модель весит больше RAM этого ПК: при недостатке файлового кэша возможны повторные
чтения. Большой batch prefill позволяет использовать загруженного эксперта сразу
для нескольких токенов; его пользу и расход VRAM нужно измерять на реальном запросе.

## Сборка и подготовка

Нужны CMake, C++ compiler и CUDA toolkit. На этом ПК используются VS 2022 Build Tools,
CUDA 13.0 из `build-local/cuda-13.0` и архитектура CUDA 120. Локальный скрипт:

```powershell
.\build-local\build-deepseek4.bat
```

Для воспроизводимой сборки в терминале с настроенными компилятором и CUDA:

```text
cmake -S backends/deepseek4 -B build-deepseek4 -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=120
cmake --build build-deepseek4 --target strata-deepseek4 deepseek4_gpu_only_test -j 2
ctest --test-dir build-deepseek4 -R deepseek4_gpu_only_contract --output-on-failure
```

`STRATA_LLAMA_DIR` задаёт локальный checkout llama.cpp. По умолчанию используется
`third_party/llama.cpp`; если его нет, CMake скачивает исходники закреплённого commit.
На Linux доступна та же сборка, но она в этой работе не проверялась. HIP backend
DeepSeek здесь не собран и не проверен. CPU-only инференс не поддерживается:
без GPU доступна только отдельная проверка токенизатора `--tokenizer`.

Подготовка профиля для **этого** ПК:

```powershell
.venv\Scripts\python.exe tools/setup_deepseek4.py --model-dir H:/deepseek-v4-flash-0731/UD-Q8_K_XL --cuda-dir build-local/cuda-13.0
```

Скрипт проверяет архитектуру, номера/число частей, размер данных каждого тензора,
дубликаты и суммарное число тензоров. Проверка размеров не является проверкой
контрольных сумм. Затем экспортирует собственный токенизатор и Jinja-шаблон модели,
создаёт `strata-deepseek4.json` и `run-deepseek4.bat` (`.sh` на Linux).
`--check-only` выполняет только проверку файлов. Веса не скачиваются и не конвертируются.

Запуск DeepSeek: `run-deepseek4.bat`. Запуск Qwen: `run-q8_0.bat`.
Оба локальных профиля используют `127.0.0.1:8080`; запускать их следует по очереди.

Для облегчённой версии на этом ПК подготовлен отдельный профиль:

```powershell
.venv\Scripts\python.exe tools/setup_deepseek4.py --model-dir H:/deepseek-v4-flash-0731/UD-Q3_K_XL --cuda-dir build-local/cuda-13.0 --profile-tag ud-q3-k-xl --gpu-expert-layers 0 --expert-cache-mib 15360 --expert-stage-mib 16 --batch-size 4096
```

Он создаёт `strata-deepseek4-ud-q3-k-xl.json`, `run-deepseek4-ud-q3-k-xl.bat`, отдельные
tokenizer pack, журнал и SQLite-статистику. Профили Qwen и UD-Q8_K_XL сохраняются.
Текущий профиль выделяет 15 ГиБ VRAM кэшу отдельных матриц экспертов и 32 МиБ RAM
двум pinned-буферам передачи. Фиксированные слои экспертов в нём не используются;
все эксперты вычисляются на GPU.

Профиль DeepSeek: контекст 8192, batch 512, один host thread, эксперты подгружаются на GPU,
архив сессий до 2048 МиБ / четырёх записей, минимум 8192 МиБ свободной RAM для
создания snapshot. `--gpu-expert-layers 0` означает подгрузку всех слоёв экспертов
на GPU по мере обращения; это не отключает GPU-вычисления. Остаток VRAM нужен
контексту, вычислительным буферам и другим приложениям.

## API, чат и архив

Работают текущий web UI, OpenAI Chat Completions, Anthropic Messages, остановка,
usage/statistics и управление архивами. DeepSeek выбирается через
`"architecture": "deepseek4"`. Его stop token — ID 1. Формат tools преобразуется из
нормализованных функций Strata в ожидаемую DeepSeek оболочку `type=function`.
Завершённые DSML-блоки разбираются в типизированные arguments. Неполный или неверный
блок не превращается в исполняемый tool call. Выдача аргументов tools начинается
после получения целого DSML-блока.

Архивы разделены по хэшу `X-Strata-Session-Id`; без заголовка используется общая
безымянная сессия. Snapshot содержит состояние llama.cpp, включая compressor states.
Сохраняется граница **перед последним токеном запроса**: при повторе этот токен
пересчитывается для получения logits. Состояние используется только при точном
совпадении сохранённого префикса и session ID. Произвольная перемотка recurrent state
не применяется. Префикс активного контекста тоже может использоваться для продолжения.

Архив ограничен общим размером и числом записей, проверяет RAM/commit перед
выделением, удаляет старые записи при нехватке бюджета. Работают ручное освобождение
и существующая автоматическая очистка сервером. Активное состояние не удаляется
командой освобождения архива. В таблице его RAM-архив равен 0: KV остаётся у backend
на GPU. После перезапуска процесса snapshots теряются. SQLite-статистика сохраняется
отдельно в `data/deepseek4-usage-statistics.sqlite`.
При точном повторе существующий snapshot сохраняется без повторного выделения RAM,
в том числе если свободная память уже ниже порога для создания новых записей.

## Проверки

- 320 случаев токенизации DeepSeek совпали с токенизатором закреплённого llama.cpp.
- Для Qwen 324 случая encode и все 33 специальных токена совпали с версией до изменений.
- Реальная последовательность A → B → A: одинаковые output IDs, 15/16 токенов
  короткого запроса восстановлены из RAM; ручное удаление обоих snapshots проверено.
- Запрос 513 токенов, другой чат, повтор: одинаковый ответ, восстановлены 512 токенов.
  Это проверяет сохранение compressor states за границей 128 токенов.
- Проверены оба API, русский ответ, DSML, отмена и следующий запрос после отмены.
- Тесты Python: `python -m unittest tools.test_deepseek4 serve.test_deepseek`.
  Общий набор: `python -m unittest discover -s serve -p "test_*.py"`.
  Windows Job Object test требует видимости собственных дочерних процессов вне
  ограниченной песочницы.
- Семь выбранных CTest для Qwen Q8 PLE/native experts и conversation cache прошли.
  Полный CTest включает другие, не собранные в локальном каталоге targets.
- Тест `deepseek4_gpu_only_contract` назначает операцию на CPU и проверяет отказ
  до записи результата, затем проверяет правильный результат той же операции на GPU.

Числа скорости относятся к проверкам на указанном ПК, а не к гарантии для любого
чата. OS/file cache между запросами не очищался. Короткие ответы из двух–четырёх
токенов не используются как замер устойчивой скорости. Результаты раннего прототипа
с CPU-experts не относятся к текущему GPU-only backend.
