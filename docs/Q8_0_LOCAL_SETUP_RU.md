После настройки выполнено [исследование скорости](Q8_0_PERFORMANCE_RU.md).

32 и 56 GiB; после длинной генерации исходный бюджет 48 GiB возвращён.

Корень установки: `C:\work\git\my-repos\Strata`.

Настройки первого запуска:

- `--resident-budget-gib 48`: до 48 GiB горячих экспертов в RAM.
- `--expert-cache auto --vram-reserve-mib 1536`: размер GPU-кэша определяется по свободной VRAM.
- `--ple-io direct`: Q8 PLE читается с SSD, со штатным ограниченным кэшем строк.
- `--prefill auto`, `--spec 4`, `--spec-min-p 0.5`, `--max-context 8192`.
- Штатный профиль `data/expert-profile.bin`; словарь MTP с кириллицей.
- Веса экспертов вспомогательного MTP преобразуются штатным способом в Q2_0;
  его предложения проверяет основная модель Q8_0.
- HTTP только `127.0.0.1:8080`; имя API-модели `qwen3.8-flash-next-q8_0`.

48 GiB — бюджет резидентных экспертов, а не жёсткий предел общей памяти процесса.
Служебные веса, staging, MTP и файловый кэш Windows расходуют память дополнительно.
Холодные эксперты использует существующий файловый путь Strata; управляемый LRU-кэш
и конвейер чтения из [плана по Colibri](COLIBRI_DISK_EXPERTS_PLAN_RU.md) пока не реализованы.

## Что изменено для Q8

В [ngram.cpp](../src/kernels/ngram.cpp) добавлено распознавание Q8_0 PLE и деквантизация
пяти Q8-блоков на строку. В [ngram.hpp](../include/strata/kernels/ngram.hpp) максимальный
буфер строки увеличен со 160 до 170 байт. Поддержаны direct и mmap. Условия чтения
остальных форматов сохранены.

Пакет подготовлен штатной командой:

```powershell
.venv\Scripts\python.exe tools/iq_pack.py --gguf H:/Q8_0/Qwen3.8-Flash-Next-Q8_0-00001-of-00006.gguf --out packs/q8_0 --compat-bf16
```

Результат: 1079 записей индекса, 303 тензора обслуживаются в исходном формате;
`dense.bin` — 1485688320 байт (1,38 GiB). Экспертного `experts.bin` для основной модели нет:
эксперты читаются из исходных GGUF, дополнительная копия 119,53 GiB не создаётся.
Для слоёв 17 и 35 роли экспертов расположены в разных частях; записан индекс v4.

`conversions.json` содержит 460 преобразований: 96 точных и 364 с округлением,
включая предусмотренное загрузчиком F32 → F16 для PLE convolution. В режиме
`--compat-bf16` преобразованы 363 малые проекции (1,22 GiB). Эксперты, основные
нативные проекции и таблица PLE сохраняют исходные байты Q8_0. Это не полностью
одинаковая численная схема с произвольным другим GGUF-движком.

Для сборки использованы MSVC 14.44 (Visual Studio Build Tools 2022), CUDA 13.0,
CMake 4.4.3, Ninja 1.13.2, `CMAKE_CUDA_ARCHITECTURES=120`.
Компоненты CUDA взяты из [официального манифеста NVIDIA](https://developer.download.nvidia.com/compute/cuda/redist/redistrib_13.0.0.json),
SHA256 всех архивов проверены. Драйвер не менялся. Локальная команда повторной сборки:

```powershell
build-local\build-q8.bat
```

Файлы `.venv`, `build-local`, `build`, `engine`, `packs`, `mtp`, конфигурация и bat-файл
являются локальными результатами настройки и исключены из Git существующим `.gitignore`.
Они нужны для работы этой установки; одного копирования репозитория на другой ПК недостаточно.

## Первый запуск: выполнен

3 октября 2026 года, около 15:49 (Asia/Yekaterinburg), модель загрузилась и ответила через API.
Сервер оставлен работающим в фоне.

- Веб-интерфейс: <http://127.0.0.1:8080/>.
- OpenAI API base URL: `http://127.0.0.1:8080/v1`.
- Имя модели: `qwen3.8-flash-next-q8_0`; ключ не требуется при этом локальном запуске.
- `/health`: `status=ok`, `loaded=true`, `max_context=8192`.
- `/v1/models`: модель зарегистрирована, вход и выход — текст. Vision не настраивался.
- Windows подтвердила слушающий адрес `127.0.0.1:8080`, а не внешний интерфейс.
- Повторный запуск после остановки: `run-q8_0.bat`. Пока этот сервер работает,
  достаточно открыть адрес выше; второй процесс на том же порту не нужен.

Запрос: «Ответь одним словом: столица Франции.», `temperature=0`, `reasoning_effort=none`,
`max_tokens=16`, потоковый ответ. Получен текст **«Париж»**.
Первый фрагмент текста — через 5,359 с, весь HTTP-запрос — 6,406 с.
По журналу движка: prompt 21 токен за 5178 мс (4,1 токена/с), generation 4 токена
за 1206 мс (3,3 токена/с), приняты 3 из 3 draft-токенов. Счётчик движка включает
служебные токены, поэтому он отличается от числа видимых фрагментов текста.

Это один короткий проверочный запрос после загрузки, без сброса файлового кэша ОС.
Он подтверждает работоспособность prefill, decode и API; устойчивую скорость на длинных
диалогах и качество по сравнению с другим движком этот запуск не измеряет.
Запрос, SSE-события и времена сохранены в `build-local/smoke-q8-result.json`.

Фактическое размещение по журналу:

| Уровень | Эксперты | Объём |
| --- | ---: | ---: |
| GPU | 4024 | 19,57 GiB VRAM |
| Резидентная RAM | 9868 | 48,00 GiB, page-locked |
| Файловый путь | 10684 | около 51,96 GiB весов в GGUF |

Prefill выбрал chunk 8192 и заимствует 819 GPU-слотов (3,98 GiB).
После полной загрузки движок сообщил 1560 MiB свободной VRAM. В снимке после запроса
`nvidia-smi` показал 2169 MiB свободной VRAM, Windows — 33381440 KiB свободной RAM
(31,84 GiB). Это свободная память всего ПК на тот момент, с учётом других приложений.
48 GiB нельзя трактовать как полный физический расход Strata: CUDA page-locked память
и WDDM также не следует оценивать по одному числу Working Set процесса.

При заполнении RAM-кэша свободная RAM временно снижалась до примерно 5,55 GiB;
после освобождения отображённых страниц и запроса восстановилась. В журнале первого
запуска есть автоматическое уменьшение GPU-кэша с 4570 до 4024 слотов, чтобы сохранить
резерв. Итоговое размещение сформировалось успешно, перехода всего RAM-кэша на mmap не было.

Журнал запроса подтверждает чтения файлового уровня: 2671 blob read и 21,0% попаданий
decode в GPU-кэш. Это внутренние счётчики движка; они не измеряют физические байты NVMe,
поскольку mmap-чтение может обслуживаться файловым кэшем Windows.

Все 31 исходных MTP-тензора проверены по закреплённым SHA256; получен штатный runtime:
`experts.bin` 707788800 байт, `dense.bin` 116099072 байта, словарь 58963 токена.
Журналы: `logs-mtp-parallel.log`, `logs-mtp-pack.log`, `logs-q8-server-out.log`,
`logs-q8-server-err.log`, `logs-q8-smoke.log`, `strata-q8_0.log`.

Для освобождения памяти модель можно выгрузить через локальный API:

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8080/v1/unload -ContentType application/json -Body '{}'
```

Сервер останется доступен, следующий запрос снова загрузит модель.
