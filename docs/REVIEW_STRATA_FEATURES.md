**Прирост получился благодаря сочетанию трёх вещей: умному размещению экспертов в памяти, одновременной работе CPU и GPU и генерации нескольких проверенных токенов за один проход.** Strata — полноценный специализированный движок на C++/CUDA, использующий в том числе код `llama.cpp`/`ggml`.

Я посмотрел исходники, техническую статью и файлы замеров. Скорость самостоятельно не воспроизводил; числа ниже — результаты автора.

Сначала важная особенность самой модели. Qwen3.8-Flash-Next — **MoE: 125 млрд параметров, но около 6 млрд активны на один токен**. В каждом из 48 слоёв выбираются 10 экспертов из 512, плюс работает один общий эксперт. Поэтому хранить нужно огромную модель, а вычислять на каждом шаге — небольшую её часть. Это и позволяет эффективно распределять работу между разными видами памяти. [Архитектура Qwen](https://huggingface.co/Qwen/Qwen3.8-Flash-Next#model-overview).

**1. Самые востребованные эксперты постоянно находятся на GPU**

Strata размещает данные так:

| Где  | Что хранится                                                                                        |
| ---- | --------------------------------------------------------------------------------------------------- |
| VRAM | Постоянно используемые части модели, состояния, вспомогательный MTP-слой и кеш популярных экспертов |
| RAM  | Все 24 576 экспертов; для IQ3_XXS это около 43 ГБ                                                   |
| SSD  | Отдельная таблица n-грамм размером 28,8 ГБ, из которой нужны лишь отдельные строки                  |

Здесь решающее свойство — **эксперты выбираются неравномерно**. Небольшая часть используется гораздо чаще остальных.

В замере IQ3_XXS при 4K в VRAM помещались 3511 экспертов — примерно **14% от общего количества**, но они обслуживали около **71% обращений**. Поэтому относительно небольшой кеш снимает большую часть работы с CPU.

Кеш адаптируется к разговору: движок считает обращения и заменяет редко используемых экспертов более востребованными. В коде это реализовано явно, включая затухание старой статистики и асинхронную загрузку замен. [Реализация адаптации](C:/work/git/my-repos/local-inference/Strata/src/program/generate.cpp:3544).

**2. Отсутствующий в VRAM эксперт не обязательно приходится целиком пересылать на GPU**

После выбора экспертов работа делится на три части:

- Экспертов, уже находящихся в VRAM, считает GPU.
- Часть отсутствующих копируется из RAM на GPU через PCIe.
- Остальных считает CPU непосредственно из RAM.

Эти операции перекрываются по времени. Для IQ-квантов по умолчанию примерно 55% промахов кеша направляются на GPU; остаток обрабатывает CPU. Это полезно, поскольку распаковка сложных IQ-форматов нагружает процессор, оставляя часть пропускной способности RAM свободной.

**Именно эта оптимизация дала автору рост IQ3_XXS с 56 до 65 токенов/с при 4K.** Он использовал отдельный механизм асинхронного копирования GPU, чтобы передача весов шла одновременно с вычислениями. [Диспетчеризация в коде](C:/work/git/my-repos/local-inference/Strata/src/core/expert_source.cpp:251), [статья, раздел 6, пункт 9](C:/work/git/my-repos/local-inference/Strata/docs/paper/Strata-Paper.pdf).

При этом считаются все выбранные моделью эксперты: ускорение здесь достигается выбором места исполнения.

**3. MTP позволяет переиспользовать прочитанные веса для нескольких токенов**

У модели есть собственный вспомогательный слой **Multi-Token Prediction**. Он недорого предлагает несколько следующих токенов. Strata затем:

1. Пропускает до трёх предложенных токенов через основную модель одним пакетом.
2. Принимает совпавшее с её предсказаниями начало.
3. Отбрасывает продолжение после первого несовпадения.

Почему это быстрее: значительную часть весов можно прочитать один раз и применить сразу к нескольким токенам. Если несколько токенов выбрали одного эксперта, его веса также используются совместно.

Для IQ3_XXS при 4K получалось в среднем **3,24 выходных токена за раунд длительностью около 49 мс** — отсюда примерно 65,6 токена/с.

Отдельный выигрыш от MTP автор оценивает в **1,6–1,8 раза** в своих экспериментах. В проверках с жадным выбором токенов спекулятивный вывод совпадал с обычным выводом движка. [Устройство проверки](C:/work/git/my-repos/local-inference/Strata/include/strata/core/verify.hpp:3), [статья, разделы 3.3 и 6](C:/work/git/my-repos/local-inference/Strata/docs/paper/Strata-Paper.pdf).

**4. Он оптимизировал небольшие, но многократно повторяющиеся операции**

Внутри каждого токена проходят десятки слоёв, поэтому задержки запуска и синхронизации быстро накапливаются. Strata использует:

- **CUDA Graphs:** заранее записанную последовательность вычислений для всего прохода.
- Обмен сигналами между CPU и GPU через общую закреплённую память.
- Объединение нескольких операций в одно CUDA-ядро.
- Специализированные CPU-ядра с AVX-512/VNNI и обработку нескольких токенов за одно чтение весов.

Есть показательный нюанс: файл **IQ3_XXS содержит тензоры разных форматов**, в том числе Q2_0. По статье автора, отдельное векторизованное ядро для таких проекций оказалось примерно в семь раз быстрее скалярного варианта использованной версии `ggml`. Это ускорение конкретной операции, а не всей модели. [CPU-ядро](C:/work/git/my-repos/local-inference/Strata/src/kernels/cpu/expert.cpp:550).

То есть «тот же квант» сохраняется, но способ его вычисления существенно меняется.

С цифрами из новости всё действительно так:

| Вариант | Контекст в замере |         Генерация |
| ------- | ----------------: | ----------------: |
| IQ3_XXS |          около 4K | **65,6 токена/с** |
| IQ3_XXS |        около 128K | **44,8 токена/с** |
| Q2_0    |        около 128K | **65,1 токена/с** |

Это подтверждается [исходным JSON результатов](C:/work/git/my-repos/local-inference/Strata/bench/results/2026-09-24-final/matrix.json). При длинном контексте память состояний вытесняет экспертов из VRAM, а доля принятых MTP-предсказаний падает — обе причины замедляют генерацию.

**Точно разложить весь переход «15 → 65» на независимые множители по опубликованным данным нельзя.** Исходные 15 токенов/с — предыдущий результат автора с `llama.cpp`; полноценного сопоставления с зафиксированными версиями, одинаковыми настройками и последовательным отключением каждой оптимизации я не нашёл. Таблица Strata построена на одном задании для каждой длины контекста и 256 выходных токенах. [Исходное сообщение автора](https://www.reddit.com/r/LocalLLaMA/comments/1wp7zyb/qwen38flashnext_on_12gb_vram_65_tokens_per_second/), [методика](C:/work/git/my-repos/local-inference/Strata/docs/DETAILS.md:12).

Моя оценка: **это содержательная инженерная разработка для большой разреженной модели на компьютере с небольшой VRAM**. Автор совместил известные методы и тщательно подогнал их друг к другу: сократил чтение весов из RAM, распределил оставшуюся работу между CPU/GPU и амортизировал её на несколько токенов. Именно эта специализация объясняет результат; универсального ускорения любых моделей в четыре раза из него не следует.
