# MiMo: плотное размещение expert cache

Измерено **2026-10-07**, Asia/Yekaterinburg, Windows, RTX5090 32 ГБ,
128 ГБ RAM. Модель: `H:\models\mimo-v2.6-flash\MiMo-V2.6-Flash-RL-GSQ-RCO-3.5bit.gguf`,
134 982 426 368 байт. CUDA13.0.48, sm120, Unsloth `86ebfef2`.

В итоговом ABBA новый allocator дал **6,434 → 6,952 ток/с (+8,1%)** без MTP.
Полезные веса в кеше выросли с9,855 до12,370 ГиБ при том же физическом бюджете
около12,9 ГиБ; decode H2D уменьшился на16,7%. В engine включён default16.
Все выходные IDs и сохранённые F32 logits этого сравнения совпали побитово.

## Что изменено

Раньше каждая матрица эксперта получала отдельный CUDA allocation с округлением
до2 МиБ: payload2,625/3,4375/4,25 МиБ занимал4/4/6 МиБ. Теперь матрицы одного
размера размещаются в общих блоках с целевым размером16 МиБ. Например,
четыре матрицы по3,4375 МиБ помещаются в блок14 МиБ; три по4,25 — также в14.
Slots выровнены до256 байт, физические блоки — до2 МиБ. Конечный блок может
уменьшаться до остатка бюджета. Живые указатели не перемещаются.

Allocator ищет свободные slots только среди неполных блоков нужного размера.
Сначала заполняется наиболее полный блок; при равенстве выбирается меньший
адрес. Пустой блок освобождается. Кеш сохраняет прежние LRU, route pins,
reuse подходящей записи и публикацию только после завершённого fill.
Частотная история, групповые D2D-копии и compaction не добавлены.

`cache_bytes` учитывает весь зарезервированный блок, включая пустые slots и
padding. `cache_slot_bytes` — живые slots; `cache_payload_bytes` — сами веса.
Live NVML clamp, запас5%+256 МиБ и резерв3 ГиБ для ещё не созданного workspace
сохранены. CPU обслуживает I/O, scheduling и sampling; модельные матрицы
вычисляет GPU. GPU audit не обнаружил CPU model nodes.

## Итоговый ABBA

Один executable, порядок старый→новый→новый→старый (`0,16,16,0`). В каждом
процессе три темы: счёт, Python, русский текст. Для каждой один первый запрос
исключён как прогрев, затем три измеренных запроса по32 output tokens.
Всего48 запросов,1536 выходных токенов; на каждый allocator18 измеренных
запросов и558 decode steps. KV очищается между запросами, expert cache остаётся.

Context512, batch8, F32 KV, FA on, обычный physical SWA основного engine,
greedy, cache до14 ГиБ с live clamp, mmap, reader1, chunk8 МиБ,
prefill admission off. MTP, CUDA Graphs и trace выключены.
Скорость = сумма decode steps / сумма generation time: без первого output,
prefill и загрузки модели, но с sampling и экспортом logits.

По порядку четырёх процессов скорость была6,489 /6,952 /6,952 /6,380 ток/с.
Peak VRAM нового варианта —92,68% доступного объёма, RAM —87,53%; global95%
не превышен. Это пик выборок, а не доказательство отсутствия кратких пиков.
Runtime также проверяет admission перед выделениями/копиями.

Системные disk counters ненулевые: за прогретые запросы PhysicalDrive4 прочитал
0,524 /0,157 /0,044 /0,106 ГиБ по порядку процессов. Эти счётчики включают
чужие процессы и не привязаны к файлу модели или букве H:. Поэтому результат
нельзя называть чистым тестом RAM bandwidth. Холодные запросы и смена темы
сохранены отдельно; короткий холодный `numbers` в проверке defaults потребовал
16,426с generation time на3 decode steps. Его время не включено в ABBA.

Предварительная версия с полным просмотром блоков дала5,846→6,568 ток/с
(+12,35%) в своём ABBA. В окончательной версии появился индекс неполных
блоков. Абсолютные времена разных серий меняются, поэтому разницу между
6,568 и6,952 нельзя приписать только индексу. Для итогового вывода используется
собственный контроль окончательной серии; MIMO-05/MIMO-06 не являются baseline.

## Проверки и ограничения

- 23 прежних cache cases,56 slab cases и5000 смешанных операций PASS.
  Проверены реальные размеры, pins, reuse, освобождение блоков, OOM,
  отказ fill и уменьшение бюджета.28 Python tests PASS.
- Итоговый GPU runtime:212/212 PASS. Полный корпус из6 prompts, в том числе
  русский, китайский, код и SWA249:3 509 248 F32 logits и выходные IDs
  совпали с управляемым кешем0. Ошибка запроса, cancel→fresh и unload PASS.
- ABBA: все48 запросов прошли audit памяти, delivery bytes и drain;
  IDs и сохранённые logits совпали между четырьмя процессами.
- После выбора default16 пересобран engine. Без переменной окружения и без
  переопределения cache/reader/context/batch повторён полный корпус и recovery:
  3 509 248 logits опять совпали. Hash измеренного executable `68bd03a9…`
  относится к сохранённой сборке `build-local/mimo2-slabs-measured`.
  Shipping hash и точные исходники обеих сборок записаны в validation JSON.

Ранние неудачи сохранены. В первом runtime с **выключенными slabs** повторился
известный F32 `mmap_pipe_2_256/logits` mismatch (max_abs0,00050618): bytes
совпали, численная причина не установлена. Повтор прошёл без изменения
арифметики или ослабления численных порогов; это не исправление дефекта.
Первый packed runtime провалил8 ожиданий об occupancy маленького кеша;
они предполагали отдельные allocations. Проверки адаптированы к hits или
освобождению блоков, все численные сравнения сохранены.

Некешированный native corpus остановился по global RAM guard95% до packed
части. В этом диагностическом пути нет managed mmap working-set cap.
Для итогового сравнения использован явно указанный завершённый cache0 reference.
Это объясняет ранее наблюдавшуюся свободную половину VRAM: native reference
не заполняет expert cache. Замеры производительности выполнялись с кешем.

Размер32, длинные контексты, длительное внешнее давление памяти и другие GPU
не измерены. Это оптимизация размещения, а не завершение P3/API/profile.
MTP serving остаётся off; расхождение batched target из MIMO-06 не исправлено.
96 kernel и132 graph checks относятся к прежнему этапу, здесь заново не запускались.

## Запуск и возврат к контролю

В свежей сборке `strata-mimo2` переменная не нужна: default —16.
`STRATA_MIMO_CACHE_SLAB_MIB=0` возвращает прежний allocator;
`16` выбирает проверенный, `32` оставлен для отдельного опыта.
Переменную устанавливать до запуска процесса. Это default отдельного pipe engine;
setup/API profile пока отсутствует.

```powershell
$mimoModel = 'H:\models\mimo-v2.6-flash\MiMo-V2.6-Flash-RL-GSQ-RCO-3.5bit.gguf'
python -m tools.benchmark_mimo2_cache --build build-local/mimo2-cuda --model $mimoModel --cuda-bin build-local/cuda-13.0/bin/x64 --order 0,16,16,0 --output-dir build-local/mimo2-validation/slab-abba-new
```

Каталог результатов должен быть новым. Контрольные `check_mimo2_engine` и
`check_mimo2_cuda` по умолчанию явно задают0; для slab validation передать
`--cache-slab-mib 16`. Для cached reference дополнительно указать
`--reference-dir <completed-run> --reference-mode pinned`.

Следующий опыт без MTP — tensor-batched delivery для уменьшения D2D/fences,
с отдельной проверкой lifetimes. Затем частотный допуск. Арифметику и CUDA
Graphs одновременно с этими изменениями не менять.
