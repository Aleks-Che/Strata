## Что реализовано

Кешированные матрицы и их guard tails одного scheduler input объединяются
в `cudaMemcpyBatchAsync`. Это сокращает число вызовов CUDA, но не объём
копируемых весов. Источники защищены route pins, назначения не пересекаются.
`cudaMemcpySrcAccessOrderStream` сохраняет зависимость от предыдущей загрузки
guard buffer. Копии внутри пакета независимы и не требуют определённого порядка.

Ring → scratch остаётся отдельной доставкой: слот нельзя возвращать producer,
пока его consumer event не завершён. Cache admission/fills выполняются после
прежней общей fence. При отмене и ошибке потоки завершаются до освобождения pins
и повторного использования scratch. CUDA ниже13 поддерживает обычный режим0,
но отклоняет явно запрошенный режим1. Математика модели остаётся на GPU.

В первом варианте пакет отправлялся после доставки misses. Во втором, который
сохранён в исходниках, пакет отправляется **до ожидания misses**. Это позволяет
уже имеющимся в VRAM данным копироваться параллельно с H2D. Оба варианта прошли
полный corpus и собственную ABBA; первый оставлен в архиве эксперимента.

Добавлены счётчики `pipeline_d2d_batch/batches/ranges`, checker option
`--d2d-batch`, benchmark axis `d2d` и `--fixed-pack-guards`. Последний необходим,
чтобы новые сравнения binary/chunk не отключали guard batching по историческому
default benchmark. Defaults самого engine этим не меняются.

## Скорость без трассировки

Context512, batch8, F32 KV, FA on, greedy, no draft, mmap/reader1/chunk8,
slab16, decay65536, tensor delivery и packed guards включены. Prefill admission,
early refill и grouped fills выключены. Три темы: счёт, код, русский текст;
на тему два исключённых прогрева и три измеряемых ответа по32 токена.
Каждый запрос получает свежий KV, expert cache сохраняется между запросами.
Скорость — сумма31 decode steps на ответ, делённая на generation time;
загрузка, prefill и первый выходной токен исключены, sampling/logits export включены.

## Что показала трассировка

Trace теперь пропускает первые N графов через `--trace-skip-graphs`, повторно
использует CUDA events и разделяет H2D, compute, cached D2D, ring D2D, sync fills.
Для ring D2D маркер стоит после `cudaStreamWaitEvent(ready)`, перед копией.
В общем transport добавлен необязательный observer; другие backend его не задают.

Сопоставимая пара: code prompt31 токен, cache11264 МиБ, два прогрева по32 выхода,
затем третий запрос. Пропущено74 графа: два полных запроса и третий prefill.
Записано5 decode graphs; таблица усредняет последние4, исключая первый с
созданием пула событий. Сводки пяти графов и SHA raw trace сохранены в JSON.

| Среднее на записанный decode graph | Обычные копии | Ранний пакет |
|---|---:|---:|
| Cached D2D submissions | 1423,75 | 138 |
| Cached D2D intervals | 13,885 мс | 21,184 мс |
| Ring D2D intervals | 6,227 мс | 5,260 мс |
| H2D intervals | 42,688 мс | 45,044 мс |
| Compute intervals | 16,125 мс | 17,012 мс |
| H2D/D2D intersection | 8,859 мс | 14,868 мс |
| H2D/compute intersection | 0,0118 мс | 0,0057 мс |
| Общий span | 109,096 мс | 110,822 мс |

Это интервалы CUDA events на реальных streams с влиянием CPU/driver dispatch,
а не чистая пропускная способность памяти или профиль отдельных kernels.
Пул событий может расширяться и после первого графа. Числа не складываются:
операции перекрываются, а span содержит промежутки без записанной GPU-работы.
Сравнение ток/с выше выполнялось с trace off.

Ранняя отправка сохранила больше пересечения H2D/D2D, но сами пакетные intervals
оказались длиннее. Почему именно этот CUDA API дороже на данной системе,
по event trace установить нельзя. Существенный H2D/compute overlap по-прежнему
не подтверждён; экономию только на числе CUDA-вызовов обещать нельзя.

## Корректность и ограничения

- Две ABBA:120 ответов,3840 output IDs и585891840 значений F32 logits;
  в каждой серии они совпали побитно с её контролем.
- Оба варианта:6 full-model corpus cases и3509248 logits каждый, exact с
  сохранённым `frequency-corpus`; cancel/error → fresh request и unload прошли.
- Поздний вариант:224 runtime off /228 on PASS. Ранний:224 off PASS;
  первый on —227/228, повтор228/228 PASS. Дополнительные4 случая проверяют
  drain/recovery после ошибки уже отправленного D2D-пакета на F32 и mixed weights.
- Byte audit проверяет фактический GPU scratch, включая guards; GPU-only audit
  проверяет отсутствие CPU вычислительных узлов. CPU7 CTest и Python30 PASS.

Неудачный `f32/file_pipe_1_256/logits` сохранён: max_abs0,0005061784759163857,
nmse5,205076543895109e−7,17472 отличающихся значений, worst12975. Это та же
численная сигнатура, которая возникала в прежних режимах без этой оптимизации.
Совпадение сигнатуры не устанавливает причину; повтор PASS не означает исправления.
Пороги проверки не ослаблены. Отдельная прежняя mixed-диагностика также открыта.

Проверка относится к тому же quantized graph, context512 и greedy. Она не
принимает MTP/DFlash, API, большие контексты или длительный pressure stress.
