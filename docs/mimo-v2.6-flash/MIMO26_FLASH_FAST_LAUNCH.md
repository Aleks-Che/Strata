# Запуск MiMo с Q4 MTP: профиль замера10,93 ток/с

Двойной щелчок по **`START-MIMO26-Q4-MTP.bat`** в корне репозитория.
Откроется консоль, загрузится модель и Q4 MTP. После сообщения «Готово»
введите запрос и нажмите Enter. Ответ появится целиком после расчёта.
Выход — `/exit` или Ctrl+C; дочерний engine завершается и освобождает память.

Это консольный запуск экспериментального MIMO-17. Каждый запрос независимый;
веса и expert cache остаются загруженными между запросами, история диалога
не сохраняется. HTTP API, веб-чат и streaming с этим MTP ещё не подключены.

## Сохранённый профиль

Файл `strata-mimo26-q4-mtp-10_93.json` предназначен для
`tools.run_mimo2_profile`, не для `serve.server`.

| Параметр | Значение |
|---|---|
| Основная модель | `H:/models/mimo-v2.6-flash/MiMo-V2.6-Flash-RL-GSQ-RCO-3.5bit.gguf` |
| MTP | `H:/models/mimo-v2.6-flash/mtp-MiMo-V2.6-Flash-MOPD-Q4_0.gguf`, первая обученная голова |
| Draft depth / cutoff | 1 /0.7 |
| Target head | Проекция по столбцам, `target-head-columns1` |
| GPU cache | Запрос14ГиБ, фактический размер ограничивается свободной VRAM |
| RAM / VRAM | Глобальный предел95%, с резервами движка |
| Transport | mmap, reader1, chunk8МиБ, slab16МиБ, tensor delivery1, packed guards1 |
| Cache policy | Decay65536, prefill admission/grouped fills/early refill/D2D batching off |
| Контекст / batch / KV | 512 /8 /F32, полный физический SWA, FA on |
| Генерация | Greedy, thinking off, TF32/CUDA Graphs off |
| Ответ по умолчанию | До128 токенов; `--max-tokens` меняет предел в диапазоне1..128 |

Матрицы вычисляются на GPU. CPU читает веса, управляет передачами,
токенизирует запрос и декодирует полученные token IDs в текст.

Используется сохранённая сборка
`build-local/mimo2-target-head-measured/build-local/mimo2-cuda`.
Launcher проверяет SHA256 executable и manifest. Если snapshot удалён или
изменён, запуск остановится с указанием файла; автоматической подмены текущей
сборкой нет. Исходный production executable и его настройки не меняются.

Результат **10,929 ток/с** измерен на Ryzen9 9950X, RTX5090 32ГБ,128ГБ RAM
в MIMO-17. Это прогретая генерация короткого corpus, не обещание скорости
каждого запроса. Подробные условия и ограничения — в
[MIMO26_FLASH_TARGET_HEAD.md](MIMO26_FLASH_TARGET_HEAD.md).
Все измеренные ускорения и состав этого профиля собраны в
[отдельной сводке](MIMO26_FLASH_SUCCESSFUL_OPTIMIZATIONS.md).

У этого исторического варианта сохраняется известное расхождение target batch2
с последовательным oracle. Исправления MIMO-18 здесь не включены: по просьбе
пользователя закреплён именно вариант замера10,93. Для MIMO-18 есть отдельный
[отчёт](MIMO26_FLASH_TOKENWISE.md); результаты разных серий не определяют
абсолютный предел возможной скорости.

## Параметры запуска

Проверить пути, хеши сборки и GGUF contracts, не загружая веса в GPU:

```powershell
.\START-MIMO26-Q4-MTP.bat --check
```

Один запрос и выход:

```powershell
.\START-MIMO26-Q4-MTP.bat --prompt "Назови столицу Франции одним словом." --max-tokens 32
```

Многострочный запрос из UTF-8 файла:

```powershell
.\START-MIMO26-Q4-MTP.bat --prompt-file "C:\path\prompt.txt" --max-tokens 128
```

Для этого probe должно выполняться `prompt_tokens + max_tokens + 8 <=480`.
Слишком длинный запрос отклоняется до передачи в engine; текст молча не
обрезается. При ответе до128 токенов остаётся344 токена на prompt вместе
с шаблоном. Более длинный контекст требует отдельной реализации и проверки.

Повторить сохранённый прогон MIMO-17:

```powershell
.\START-MIMO26-Q4-MTP.bat --benchmark
```

Это15 запросов: count/code/ru, два прогрева и три измеряемых повтора каждого,
по32 выходных токена. Используются сохранённые IDs из
[profiles/q4-mtp-10_93-requests.json](profiles/q4-mtp-10_93-requests.json).
Итог исключает прогревы, загрузку, prefill и первый выходной токен;
экспорт logits включён, как в исходном замере. Это один процесс выбранного
режима, а не повтор всей сравнительной серии A B C C B A.

Каждый запуск создаёт новый каталог `build-local/mimo2-runs/<дата-id>`:
`run.json`, `stdout.log`, `stderr.log`; benchmark также сохраняет F32 logits.
В `run.json` записываются настройки, IDs/текст ответов, timing и sampled memory.
При превышении95% runner останавливает только свой engine.

Нужны существующие `.venv` с numpy/psutil/jinja2/regex, сохранённая сборка,
CUDA DLLs из `build-local/cuda-13.0/bin/x64` и оба GGUF по путям в профиле.
Launcher не скачивает веса и не пересобирает backend.

## Проверка launcher, 7 октября2026

Проверены запуск `.bat` из другого каталога, SHA256/GGUF contracts,
отклонение слишком длинного prompt, два последовательных консольных запроса
и `/exit`, затем полный15-request `--benchmark`. Все544 выходных IDs этих
17 запросов совпали с соответствующими ответами сохранённого MIMO-17.
GPU/drain audit PASS; оба engine завершились с кодом0.

В этом одиночном проверочном benchmark получено **9,405 ток/с**,
cache10,518ГиБ и H2D1,155ГиБ на выходной шаг. В исторической серии10,929
cache составлял11,882ГиБ и H2D1,025ГиБ. Профиль и SHA executable совпадают;
историческая скорость не воспроизведена этим запуском. Это не сравнение
launcher A/B и не доказательство причины различия.
Пики sampled global памяти: VRAM92,66%, RAM92,41%, ниже95%.
[Данные проверки](MIMO26_FLASH_FAST_LAUNCH_VALIDATION.json).
