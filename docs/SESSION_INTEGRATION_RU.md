# Интеграция статистики и архива сессий

Дата: 3 октября 2026 года.

Источник функций — соседняя копия
`C:\work\git\my-repos\local-inference\Strata`, её модули `usage_stats.py`,
`archive_policy.py`, сервер, интерфейс, код архива и тесты. За основу поведения взяты
окончательные ревизии её `docs/conversation-cache-integration.md` и
`docs/usage-statistics.md`. Старые эксперименты с удалением отдельных checkpoints
не переносились: освобождается сохранённая сессия целиком.

## Что доступно

- Вкладка **Statistics**: обработанные входные токены, повторно использованный
  контекст, выходные токены, число запросов и графики по периодам. Счётчики
  сохраняются в SQLite и восстанавливаются после перезапуска.
- **Monitor → Session archive**: активная сессия и сохранённые снимки, их размер,
  время последнего использования, причины отказа в сохранении, ручное освобождение.
- Автоочистка по времени простоя, с сохранением настройки на диске. По умолчанию
  выключена; её можно включить в окне архива. Активная сессия не удаляется.
- Необязательный заголовок `X-Strata-Session-Id` в OpenAI и Anthropic API.
  У веб-чата постоянный ID; **New chat** создаёт новый, **Undo** возвращает прежний.
- Показатели Windows commit отдельно от физической RAM, стадии сохранения и
  восстановления, время переноса и диагностика нехватки памяти.

Кэш экспертов и архив диалогов — разные части движка. Этот перенос ускоряет
повторное чтение уже обработанного контекста при переключениях; он не устраняет
чтение холодных экспертов Q8_0 с SSD во время генерации.

Снимки сессий хранятся в RAM. Остановка или выгрузка модели удаляет их. На диске
остаются статистика и настройки автоочистки, а не KV-состояние модели.

## Совместимость с нашей версией

Файлы альтернативного движка не заменяли текущие целиком. Сохранены Q8_0 PLE,
ускоренный повторный захват неизменённых KV-страниц, K8V4/rotated INT8, исправление
вытеснения старых копий одной истории, MCP, ограничение thinking, API monitor,
load/unload и существующая поддержка разделения модели по GPU.

Полный архив сессий по-прежнему работает на одном GPU. Идентификаторы сессий
не отменяют проверку совпадения токенов, изображений и режима steering.
Восстановление также проверяет, что MTP действительно содержит необходимый
диапазон KV. Это учтено и в новом пакетном пути prefill нашей версии.

## Локальный запуск

В `strata-q8_0.json` добавлены лимит архива **2048 МиБ**, до **4** сохранённых
снимков и минимум **8192 МиБ** свободной физической RAM при сохранении.
Память выделяется по мере необходимости. Если снимок не проходит проверку бюджета
или свободной памяти, запрос продолжает обычную обработку без парковки.
Резидентный кэш экспертов остаётся 48 GiB, контекст 8192, MTP `spec=4`.

Статистика: `data/usage-statistics.sqlite`. Настройка автоочистки создаётся рядом
с конфигом после изменения в интерфейсе. Тестовые запросы выполнялись с отдельной
БД и не входят в рабочую статистику. Для запуска используется `run-q8_0.bat`.

## Проверка на этом ПК

Windows, Ryzen 9 9950X, RTX 5090 32 GiB, 128 GiB RAM; модель Q8_0 из `H:\Q8_0`,
48 GiB резидентных экспертов, MTP, архив 2048 МиБ. В тесте адаптация экспертов
отключена (`--adapt-swaps 0`) для сравнения ответов; рабочий конфиг её сохраняет.

Первый сценарий: A → B → A, по 32 выходных токена, 27 входных токенов в A.
Повторный A использовал **20** токенов из RAM-архива, ответ совпал с первым A.
Сохранение перед восстановлением заняло **36,5 мс**, восстановление **16,9 мс**.
Освобождение сохранённого B уменьшило учтённый архив с **237 820 688 байт до 0**;
активная сессия сохранилась. Автоочистка затем освободила ещё один настоящий
снимок. Для её проверки время отсечения было сдвинуто в тесте, ожидание часа
не выполнялось. Счётчики после закрытия и повторного открытия SQLite совпали:
4 запроса, 84 обработанных входных, 20 cached, 128 выходных токенов.

Это функциональная проверка коротких сессий, не замер общего ускорения модели:
между запросами прогревались кэши весов и ОС. Исходные результаты находятся в
`bench/results/2026-10-03-session-integration/`.

Повторная проверка с **1427** входными токенами и промежуточными checkpoints
каждые 512 токенов также прошла. После A → B → A восстановлены **1420** токенов;
сохранение заняло **37,8 мс**, восстановление **23,5 мс**, ответ из 32 выходных
токенов совпал с первым A. Проверки ручного освобождения, автоочистки и SQLite
повторены. Длинные окна, близкие к пределу 8192, и HIP/multi-GPU в этом переносе
отдельно не измерялись.

Итоговая проверка: **190** тестов Python, из них **188 прошли**, **2 пропущены**;
**7 из 7** выбранных CTest прошли: cache policy, memory admission, GPU snapshots,
snapshot validation, PLE reader, Q8_0 expert parity и Q8_0 PLE. `node --check`
для `serve/web/app.js` прошёл. В браузере проверены Statistics, выбор периода,
окно архива, ручное освобождение и изменение интервала автоочистки с клавиатуры.
Все браузерные данные были тестовыми на отдельном порту 8081.

Собранный `engine/strata.exe` обновлён. После проверок рабочий и тестовые процессы
остановлены; порты 8080 и 8081 освобождены.
